## 1. 方位は、発進方向から決める

**スタート区画からマイクロマウスが発進する向きを北とする。**

- **マイクロマウスは必ず北の方向へ発進する**
- 北がひとつ決まれば、迷路の東西南北は自動的に決まる

これが方位の唯一の定義である。迷路の形や大きさによらず、この一点から全部が決まる。

## 2. 上下左右

迷路を上から見たとき、次のように言い換えてよい。

| 方位 | 言い換え |
|---|---|
| 北 | 上 |
| 南 | 下 |
| 東 | 右 |
| 西 | 左 |

「上から見て」が前提である。**機体から見た左右ではない**（機体基準の左右は §7 で別に定める）。

## 3. 座標軸

**東方向を X 軸の正方向、北方向を Y 軸の正方向とする。**

```
                 北 (+Y)
                   ↑
                   │
      西 ──────────┼──────────→ 東 (+X)
                   │
                   ↓
                 南
```

## 4. 右手系

**工学分野では右手系を用いるのが慣習であり、マイクロマウスも右手系とする。**

右手系と決めたことにより、Z 軸の向きは自動的に決まる。

**Z 軸は迷路面に垂直で、上方が正。**

検算（右手系の定義 X × Y = Z）:

```
東 × 北 = 上          ✓ 右手系として整合する
```

床から天井へ向かう向きが +Z である。重力は −Z 方向に働く。

## 5. 原点

**座標原点は、スタート区画の左下（南西）の柱の中心とする。**

スタート区画は迷路の南西の隅にあるので、これは**迷路全体の南西の角にある柱の中心**と一致する。

柱は 12 mm 角である。原点はその**中心**であって、角ではない。

## 6. 区画座標と実座標

### 区画座標

- 単位: 区画
- 表記: $(x, y)$ — 整数
- $(0,0)$ = スタート区画（南西の隅）
- $+x$ = 東、$+y$ = 北
- 16×16 の迷路なら $(0,0)$ 〜 $(15,15)$

### 実座標

- 単位: メートル
- 表記: $(x_m, y_m, z_m)$
- 原点は §5 のとおり

### 変換

区画 $(x, y)$ の**中心**の実座標は、区画の一辺を $p$（クラシック競技では $p = 0.18\ \mathrm{m}$）として

$$
x_m = p\,x + \frac{p}{2}, \qquad y_m = p\,y + \frac{p}{2}
$$

- スタート区画 $(0,0)$ の中心 = $(0.09,\ 0.09)$
- 柱は格子点 $(p\,i,\ p\,j)$ に立つ

## 7. 角度

### ヨー角（機体の向き）

- 記号: $\psi$
- **基準（$\psi = 0$）は東、すなわち $+X$ 方向**
- **正の回転は、上（$+Z$ 側）から見て反時計回り**（右手系で $+Z$ まわりの回転の正の向き）

| 向き | $\psi$ |
|---|---|
| 東（$+X$） | $0°$ |
| **北（$+Y$）** | **$+90°$** |
| 西（$-X$） | $180°$ |
| 南（$-Y$） | $-90°$（＝ $270°$） |

**マイクロマウスの発進時の姿勢は $\psi = +90°$ である**（必ず北へ発進するため。§1）。

### 機体に固定した座標系

機体に固定した座標系も右手系とし、次のように取る。

| 軸 | 向き |
|---|---|
| $+x_b$ | 機体の**前方**（進行方向） |
| $+y_b$ | 機体の**左** |
| $+z_b$ | **上**（迷路面から離れる向き） |

検算: 前 × 左 = 上 ✓ 右手系として整合する。

$\psi = 0$ のとき機体座標と世界座標は一致する（前方が東、左が北）。
発進時（$\psi = +90°$）は、前方が北、機体の左が西を向く。

- **機体の左右と、迷路の東西は別物である。**混同しないこと
- 左センサ・右センサは**機体基準**の呼び名である

## 8. 単位

| 量 | 単位 |
|---|---|
| 長さ | メートル [m]（文書中で mm を使う場合は必ず単位を書く） |
| 角度 | 内部の計算はラジアン [rad]。文書と報告では度 [°] を併記してよい |
| 時間 | 秒 [s] |

## 9. なぜこれを明文化したか

本リポジトリは作られてから時間が経っており、**座標系を最初にきちんと定めたかどうかが
はっきりしない状態にあった。**そのため、この決定と食い違う文書やコードが残っている
可能性がある。

食い違いを見つけた場合の扱い:

1. **本書が正である。**本書に合わせて直す
2. ただし、**物理モデルや評価の結果を変えてしまう修正は、その場で直さない。**
   `docs/MODEL_VERIFICATION_PLAN.md` の改訂と検証スイートの再実行が要るため、
   教授セッションへ上げること（`CLAUDE.md` の規約）
3. **呼び名だけの食い違い**（変数名・注釈・文書の言い回し）は、気づいた者が直接直してよい

### 10-2. 埋めた空白

次の 3 つは、**これまでどこにも明文が無かった**。本書が初めて定めるものである。

1. **右手系であること。**「右手系」「左手系」という語は、制定前のリポジトリ全体で
   一度も使われていなかった
2. **Z 軸が迷路面に垂直で上方が正であること。**転倒判定のコード
   （`docs/MODEL_VERIFICATION_PLAN.md`「車体 z 軸の世界 z 成分 > 0.5」）から
   逆算するしかない状態だった
3. **機体固定座標系の軸の向き。**「前方 = $+x$、左 = $+y$」は
   `verification/TABLE_001_support_function.md:12` という検証用のノートにしかなく、
   正本には無かった。`docs/ROBOT_SPEC.md` のセンサ表は「方位角（+x 基準）」と書きながら、
   $+x$ が前方であることを明言していなかった

### 10-3. 方位のインデックスは工学系に揃えた（2026-08-23 ユーザ決定）

制定の時点では、同じ「heading」という語が **2 つの別の意味**で使われていた。

| 体系 | 0 の意味 | 増える向き |
|---|---|---|
| 方位コード（`Direction`） | 北 | 時計回り（N→E→S→W） |
| ヨー角（`heading_deg`） | 東 | 反時計回り |

**0 の意味も回る向きも逆**で、`classic/ideal.py` が `π/2 − d·(π/2)` という符号反転を
挟んでいた。マウスのプログラムでは「北を 0 として東・南・西と増やす」流儀が多いが、
**本リポジトリは工学系に統一する**（ユーザ決定）。

**`Direction` を E=0, N=1, W=2, S=3（反時計回り）へ付け替えた。**

- ヨー角と向きが揃い、**インデックス +1 が「左 90°・ヨー角 +90°」**と一致する
- `_dir_angle(d)` は **`d · π/2`** になった（符号反転が不要になった）

#### 付け替えの検収（2026-08-23）

🔴 **これは振る舞いを変えない付け替えである。**次のとおり実測で確かめた。

- 実際の大会迷路 3 面（`contest_reference` の `16MM2012CX`・`13CX`・`14CX`）で
  古典ベースラインを通しで走らせ、**付け替えの前後の結果を突き合わせた**
- 記録したもの: 走行の成否・最短走行時間・η・**指令列の全体**（最大 42001 個）・
  学習した地図・走行の局面・事故の記録
- 結果の JSON の **sha256 が前後で同一**（`19b18c03d3a9ef70…`）。**1 ビットも変わっていない**
- あわせて `tests/` 一式を実行（既知の失敗 `test_mouse_v2.py::test4_sensors` を除き全通過）
- 比較は教授セッションが、HEAD の作業ツリーを別に作って独立に測り直した

🔴 **ただし、この一致だけでは足りなかった。**下記の 10-3b を必ず読むこと。

**振る舞いが保たれた理由**（次に触る人へ）:

- `ALL_DIRECTIONS` は `(N, E, S, W)` の**名前の並びのまま**にした。
  数値が変わっても走査順は変わらないので、同順位の選び方が保たれる
- `competition/explore_cost.py` には `_NESW_ORDER = (1,0,3,2)` を置き、
  北→東→南→西の走査順を明示的に保った
- 直進 > 右折 > 左折 > 後退 の優先順は、インデックスの向きが逆になったぶん
  `+1` と `+3` を入れ替えて同じ順序を保った

#### 🔴 10-3b. 一致確認をすり抜けた回帰が 2 件あった

**付け替えの過程で、走行が実際に変わる誤りを 2 件出した。**どちらも
**上の「3 面での sha256 一致」では検出できなかった。**

| # | 何が変わったか | どう直したか |
|---|---|---|
| 1 | `_dir_angle` の**値の分枝**。南が −90° → +270°、西が −180° → +180° | `_DIR_ANGLE_RAD` の対応表にして、分枝を付け替え前と同一に固定 |
| 2 | `_turn_delta` の **180° 折返しの符号**。付け替え前は常に −π、素直な式では +π | `rel == 2` のとき −π を返すよう固定 |

どちらも**向きとしては同じで、`cos`・`sin` を取れば区別できない。**
しかし `classic/explorer.py` が `tracker.reset(heading_deg=math.degrees(psi_start))` へ
**巻き戻していない角度**を渡しているため、2π ずれた値はヨー角の積分器の初期値を変える。
180° 折返しは **+π も −π も同じ向きを指す退化した場合**で、符号を選ぶ物理的な根拠が無いが、
選んだ符号がそのまま下流のシミュレーションへ伝わる。

**なぜ sha256 の一致で検出できなかったか。**
比較に使った 3 面は競技規約どおり**すべて北向き発進**であり、
変わったのは**南向き・西向き**の分枝だった。
**一致は「北向き発進については変わっていない」ことしか言っていなかった。**

**何が検出したか。**`tests/test_classic_fast_run_profile.py` の
`test_wall_correction_mode_snap_matches_pre_blend_baseline_exactly` ──
**わざわざ南向き発進を試し**、想定のティック数（北 595・南 617）と突き合わせる検査である。
南が 617 → 1065 に変わったことで捕まえた。
置いた人が「共通コードが変わった疑い（回帰）」という文言まで添えており、その意図どおりに働いた。

🔴 **教訓（作法ではなく検査に変換済み）**:
**一致確認は、変えたものが効く場面を通っていなければ意味がない。**
`tests/test_coordinate_system.py` に、角度の**分枝そのもの**を固定する検査を 2 つ置いた
（`test_direction_code_increases_counterclockwise` の後半と
`test_turn_delta_180_uses_the_negative_branch`）。次に誰かが「素直な式」に直そうとしたら、
シミュレーションを回すまでもなくその場で落ちる。

#### 呼び分けの約束

- **方位コード**を指すときは `Direction` 型を使い、変数名を `direction` とする
- **ヨー角**を指すときは、変数名に必ず単位を付ける（`heading_deg`・`yaw_rad`）
- 文章では「方位」と「ヨー角」を書き分ける。**裸の「heading」を使わない**

### 10-4. 🔴 学習用の迷路生成器は、この取り決めに従っていない（**判断待ち**）

| 場所 | 事実 |
|---|---|
| `mouse/maze6_gen.py:44,258` | スタート区画を**四隅からランダムに選ぶ** |
| `mouse/maze6_gen.py:297` | 発進方向が 0°／90°／180°／270° の**いずれにもなる** |
| `mouse/corridor_gen.py:27,252` | 回廊生成も同様 |

スタートが $(0,0)$ 以外の隅に来ると、世界原点は迷路配列の $(0,0)$ に置かれたままなので、
**「原点 = スタート区画の南西の柱」が成り立たなくなる。**

**これは仕様に関わるため、教授セッションでは決めない。**ユーザの判断を仰いでいる。

なお実機の競技規定（NTF）でも**始点は四隅のいずれか**である
（`docs/ADVERSARIAL_MAZE_DESIGN.md:112` が引用する規定 2-3）。
§1 の「発進方向を北と呼ぶ」という定め方は、**四隅のどこから始まっても
同じ枠に載せ替えられる**ようにするものである。

### 10-5. 測定用の始動姿勢は、競技の規約とは別

`competition/model_verification.py` は多くの箇所で `heading_deg=0`（東向き）から始動している。
これは電圧ステップ応答などの**単体測定**であり、競技の発進を模擬するものではない。
競技側（`competition/evaluator.py`）は一貫して 90°（北）である。**食い違いではない。**
