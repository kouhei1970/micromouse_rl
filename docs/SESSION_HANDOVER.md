# セッション引き継ぎ規約

制定: 2026-08-10（ユーザ提案）。長時間稼働したセッションは動作が重くなり、作業の途中で停止することがある。**定期的にまとめてセッションを入れ替える**運用とし、そのための引き継ぎメモを常時維持する。

## 1. 引き継ぎメモの置き場所

各セッションは自分の現況を次のファイルに維持する（**常に最新の状態に保つ**）:

| セッション | ファイル |
|---|---|
| 教授 | `handover/professor.md` |
| 学生A（評価・古典ベースライン） | `handover/student_a.md` |
| 学生B（強化学習） | `handover/student_b.md` |

## 2. 更新の契機（いずれかに該当したら即更新）

1. **コミットしたとき**（コミット直後にメモも更新）
2. **大きな作業の区切り**（実験 1 本の完了、動画 1 本の完成、設計の確定など）
3. **教授から「まとめて」と指示されたとき**
4. **リセット（セッション入れ替え）の直前**
5. **詰まって作業を中断するとき**（ここが最重要 — 突然停止しても引き継げるように）

## 3. 書く内容（テンプレート）

```markdown
# 引き継ぎメモ: <役割名>

- 更新: YYYY-MM-DD HH:MM
- セッション開始: YYYY-MM-DD HH:MM

## 役割と担当範囲
<担当ディレクトリ、触ってよい/いけない範囲>

## いま何をしているか
<進行中のタスクと、どこまで終わったか。「実装は済んだが未検証」等の状態も>

## 未コミットの変更
<ファイル名と、それぞれ何を変えたか。中途半端な状態ならその旨>

## 直近の裁定・決定事項
<教授から受けた指示で、いま効いているもの。判断の前提>

## 詰まっている点・注意点
<エラー、原因不明の挙動、判断待ちの事項>

## 次にやること（優先順）
1. …
2. …

## 参照すべき文書
<この作業で読むべきファイルの一覧>
```

## 4. リセット（セッション入れ替え）の手順

1. 教授が「まとめてリセット」を指示する（または各セッションが自己申告）
2. 対象セッションが引き継ぎメモを**最新化してコミット**
3. ユーザが当該セッションを終了し、新しいセッションを起動
4. 教授が新セッションへ役割定義書を送る（引き継ぎメモの場所を明示）
5. 新セッションは `CLAUDE.md` → `docs/RESEARCH_PLAN.md` → **自分の引き継ぎメモ** の順に読んで再開

## 4-2. 再開時の呼びかけ（ユーザ向け・コピペ用）

**まず教授セッションだけを起動する**。学生は教授の指示で後から起動すればよい。

```
教授セッションとして再開します。handover/professor.md を読んで現況を把握し、
次の作業を進めてください。
```

学生セッションを起動したら、**教授セッションに一言伝えるだけ**でよい（学生側に直接指示する必要はない。教授が `/list-agents` で見つけて役割定義書を送る）:

```
学生セッションを起動しました
```

役割を指定したい場合は「学生A（評価担当）を起動しました」のように添える。

## 5. リセットの目安

- **稼働が長くなったとき**（目安 8〜12 時間、または動作が遅い・停止が増えたと感じたとき）
- **マイルストーンの区切り**（M1 完了時など）
- **担当範囲が変わるとき**

長さを厳密に守る必要はない。**「停止してから困る」より「区切りで自発的にまとめる」**方が安上がり、という考え方で運用する。
