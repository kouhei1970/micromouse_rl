# セッション引き継ぎ規約

制定: 2026-08-10（ユーザ提案）。**全面改訂: 2026-08-18（単独運用への移行・`docs/RESEARCH_PLAN.md` §11・§12-9）。**

長時間稼働したセッションは動作が重くなり、作業の途中で停止することがある。**定期的にまとめてセッションを入れ替える**運用とし、そのための引き継ぎメモを常時維持する。

**⚠️ 引き継ぎメモは `handover/professor.md` 1 通のみ・80 行以内・「現況」のみ。**過去分は書いた端から削除する（git 履歴が保存する。アーカイブファイルも作らない）。**更新の契機は「再開時・停止時・重大事象時」のみ**（コミットごとの更新義務は 2026-08-15 に廃止済み）。

## 1. 置き場所

| セッション | ファイル |
|---|---|
| 教授（唯一の常設セッション） | `handover/professor.md` |

**subagent は引き継ぎメモを持たない**（文脈を持ち越さないため）。subagent の成果は git コミットと実験カード・判定文書に残す。

旧マルチセッション体制の役割別メモ（`student_a.md` `student_b.md` `associate_professor.md`）は 2026-08-18 に廃止した。**内容は `ac3e9f9` に保存されている**ので復元しない。

## 2. 更新の契機

1. **再開時**（現況を確認し、ずれていたら直す）
2. **停止時**（セッション入れ替えの直前・突然の停止に備えて詰まった時点でも）
3. **重大事象時**（裁定の変更・実験の判定確定・設計の確定など、次の担当の前提が変わったとき）

## 3. 書く内容

**現況のみ。**次の 5 つが揃っていればよい（見出しは目安・80 行以内）。

```markdown
# 引き継ぎメモ: 教授セッション

- 更新: YYYY-MM-DD（状態: 稼働中 / ⏸ 停止）
- 運用規約 = `docs/RESEARCH_PLAN.md` §11・§12（§12-9 = 単独運用）

## 次の担当の最初の仕事
<1〜3 個。着手に必要な前提（設計の確定待ちなど）も書く>

## 現況
<主戦線がどこで、何が終わっていて、何が動いているか。実行中プロセス・未コミット変更の有無を明記>

## 効いているユーザ裁定
<いま判断の前提になっているもののみ。失効したものは消す>

## 詰まっている点・注意点
<原因不明の挙動、判定が反転しうる落とし穴>
```

**⚠️ 決めたことは、決めた時に `handover/professor.md` へ書く。**マルチセッション時代に、裁定をメッセージだけで流した結果、**発行者が落ちた時点で指揮側の記憶から消え、下位だけが指示どおり動いている**状態が実際に発生した（2026-08-11）。単独運用でも同じ経路が残る — **subagent へ渡した指示・判断は、subagent が終わると消える。**教授セッション側に残すこと。

## 4. リセット（セッション入れ替え）の手順

1. 引き継ぎメモを**最新化してコミット**（`git commit handover/professor.md -F -`）
2. 実行中のプロセスを確認し、あれば残すか止めるかを決めてメモに書く
3. ユーザがセッションを終了し、新しいセッションを起動
4. 新セッションは `CLAUDE.md` → `docs/RESEARCH_PLAN.md`（§11・§12）→ `handover/professor.md` → `research_notes/` の最新ノート の順に読んで再開

### 再開時の呼びかけ（ユーザ向け・コピペ用）

```
教授セッションとして再開します。handover/professor.md を読んで現況を把握し、
次の作業を進めてください。
```

## 5. リセットの目安

- **稼働が長くなったとき**（目安 8〜12 時間、または動作が遅い・停止が増えたと感じたとき）
- **マイルストーンの区切り**（章の完了時など）
- **主戦線が変わるとき**

長さを厳密に守る必要はない。**「停止してから困る」より「区切りで自発的にまとめる」**方が安上がり、という考え方で運用する。
