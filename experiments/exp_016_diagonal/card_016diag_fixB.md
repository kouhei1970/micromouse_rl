**つまり欠陥は「斜め経路の作り方」ではなく「斜め経路へ入る前の向き合わせを飛ばしたこと」である。**

## 1. 是正の設計（**実施時に詰める。起票時点では骨子のみ**）

### 1-1. 方針 — **親に任せる**

**機体の方位と経路の最初の方位が食い違うときは、斜めの分岐に入らず親の `_replan` へ委ねる。**
**親はその場旋回で向きを合わせる。向きが合った次の再計画で、斜め経路が張られる。**

```
_replan:
    if not _use_diag():            → 親へ（現行のまま）
    nodes, dirs = _plan_diag(...)
    if len(dirs) < 2:              → 親へ（現行のまま）
    ★ if 方位の食い違い > 閾値:     → 親へ（**本カードで足す 1 箇所**）
    ...（以降は現行のまま）
```

**⚠️ 自前でその場旋回を書かない。**親の実装を使う
（**書くと「その場旋回の実装」という 2 つ目の変更になる**）。

### 1-2. 閾値の決め方（**実装より前に決める**）

**閾値は探索しない。**次の 2 つのどちらかを**実装前に選んで固定する**:

| 案 | 閾値 | 根拠 |
|---|---|---|
| **(i)** | **食い違い > 0**（完全一致を要求） | **経路の最初の区間には円弧が無い**（`build_diagonal_path` は `tan_len[0] = 0` で、先頭節点に接続の円弧を置かない）。**したがって、どんな食い違いも追従則だけで吸収することになる** |
| (ii) | 食い違い > 45° | 45° までは追従則で吸収できるという見立て。**ただし見立てであって実測ではない** |

**学生A の推奨は (i)** — **(ii) の 45° は根拠が見立てだけであり、
「先頭に円弧が無い」という構成上の事実からは (i) が素直**である。
**(i) で斜めが使われなくなるようなら、それは別の欠陥として測って報告する**
（**閾値を緩める方向へ動かさない**）。
