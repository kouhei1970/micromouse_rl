## 3. 🔴 **統計設計と帯の容量が衝突する**（**起票前に実測して確かめた**）

**REQ_001 §2-3 の要求**: $n\ge60$（**判定は「完走率 100%」ではなく片側 95% 下限 $\ge$ 0.95**）。
**面を増やす方が試行を増やすより効く**（クラスタ構造・`AUDIT_015` §3）。

**R43 の帯**: 設計帯 41000–61000。**現行の `design_v4` は 20 面。**

### 3-1. **実測: この帯を同じ受理条件で回しても、20 面が上限である**

`competition/maze_gen_v3.py` を `--n-per-band 15`（＝ 層あたり 15 面・計 60 面）で
dry-run したところ、**seed 42000 で 20/60 に達した後、44400 まで 1 面も増えなかった。**

**原因は層別ではなく K 階級の目標である**:

| 制約 | 値 | 性質 |
|---|---|---|
| 層（経路比 $R$）ごとの目標 | `--n-per-band`（可変） | **引数で増やせる** |
| **K 階級（候補経路の本数）の目標** | **`{1: 4, 2: 8, 3: 8}`（合計 20）** | 🔴 **絶対数でコードに埋まっている**（`competition/macro_routes.py` 由来・大会の実測比率 19/41/41% を **20 面**へ割り当てたもの） |

**K 階級の目標が合計 20 なので、層の目標をいくら上げても 20 面で頭打ちになる。**
（現行 `design_v4` の manifest でも `k_targets` = `{"1": 4, "2": 8, "3": 8}`）

**参考（既存 manifest からの実測）**: 20 面の生成に **9764 seed** を消費している
（層ごとの採用率 0.4% / 1.8% / 3.7% / 3.5%）。**帯の残りは 10236 seed。**

### 3-2. 🔴 **裁定を仰ぐ — $n$ をどう確保するか**

| 案 | 内容 | 代償 |
|---|---|---|
| **(A)** K 階級の目標を 3 倍（`{12, 24, 24}`）にして **60 面**生成 | **帯の組成の契約（大会の比率）は保つ** | **帯の残り seed で足りるか未確認**（20 面で 9764 消費・残り 10236。**3 倍には届かない見込み**） |
| **(B)** 校正帯を **61000 超へ延ばす** | `common/seed_bands.py` 上、**41000 以降は `free`** なので**規約上は可能** | **R43 の「41000–61000」の文言を超える**（**教授の裁定事項**） |
| **(C)** **1 面あたり複数試行**（初期擾乱を変える） | 生成が要らない | **REQ_001 が「面を増やす方が効く」と警告**（クラスタ構造） |
| **(D)** $n$=20 のまま実施し、**下限 0.861 と限界を明記** | いま実施できる | **REQ_001 の判定規則（下限 $\ge$ 0.95）を満たせない** |

**私の推奨は (B)＋(A) の併用**: **K 階級の目標を層と同じ倍率で上げ、帯を必要なだけ延ばす**
（**41000 以降は free なので凍結帯も候補プールも侵さない**）。
**理由**: **(C) は REQ_001 が明示的に劣ると言っている**。**(D) は判定規則を満たせない**。
**(A) 単独では帯の容量が足りない見込み**。

> **⚠️ この見込み（(A) 単独では足りない）は既存 manifest からの外挿であり、実測ではない。**
> **裁定をいただいたら、まず dry-run で必要な seed 数を実測してから生成する。**

### 3-3. 🔴 【2026-08-14 裁定 **R43-2**】（教授。**R43 を改訂する**）

**採用 = (B)＋(A) の併用。**

| 決定 | 内容 |
|---|---|
| **校正帯** | **seed 41000 以降の free 帯**（**R43 の「41000–61000」の上限を撤廃**）。**根拠**: `common/seed_bands.py` 上 **41000 以降は `free`** であり、**凍結帯（eval・validation）も候補プール（1000–40999）も侵さない** |
| **K 階級の目標** | **比率を保って 3 倍 `{12, 24, 24}`**。**契約は「大会の実測比率 19% / 41% / 41% の維持」であって絶対数ではない**（絶対数の 3 倍はその実装） |
| 生成コードの変更 | **目標値のみ・最小に** |

**条件 3 件**:
1. **dry-run で必要 seed 数を実測してから生成する**（本カード §3-2 の但し書きどおり）
2. **生成した帯の実際の範囲・消費 seed・受理率を `freeze_record` に記録する**（§2 の慣例）
3. **(C)(D) の棄却理由もカードへ**（下記）

**(C) 1 面複数試行の棄却理由**: **REQ_001 §2-3 が明示的に警告している** —
**同じ面の反復は独立でなく（クラスタ構造・`AUDIT_015` §3）、面を増やす方が効く。**

**(D) $n$=20 のままの棄却理由**: **校正の目的に対して統計力を削る。**
**安全率は参照線全体が乗っている未校正パラメータ**であり、
**「下限 0.861 しか言えない校正」では、その上に乗る全記録の根拠として弱すぎる。**

### 3-4. **生成器の変更（最小）と、その無害性**

**`K_TARGETS = {1: 4, 2: 8, 3: 8}` の定数そのものは変更しない。**
**変えると凍結帯 `eval_v4` を再生成できなくなる**（決定性の照合 = npz の SHA-256 40/40 一致が
崩れる。`maze_gen_v2.py` を凍結記録として残したのと同じ理由）。

**代わりに `--k-scale`（既定 1）を足した**。
**既定では `K_TARGETS` と等しい辞書になるので、従来と挙動は変わらない。**

**無害性は実測で確かめる**: **既定のまま `--seed-from 1000 --seed-to 20999` を dry-run し、
採用された seed 列が凍結帯 `eval_v4` の manifest と完全に一致すること**を確認する。

## 4. 予測の事前登録（実装前に記入・**変更しない**）

> **⚠️ 作法 10 に従い、各予測で「上／帯の中／下」の 3 方向すべてに読みを与える。**
> **F-1〜F-4 は REQ_001 §2-5 の反証条件を継承し、量と許容差を付けたものである。**

| # | 予測 | 量と許容差 | 外れの向き（**全域**） |
|---|---|---|---|
| **C1** | **完走率は安全率に対して単調に落ちる** | 量 = 安全率ごとの完走率。**予測: 単調非増加**（同点は許す） | **非単調**（途中で上がる点がある）→ **測定のばらつきか、面の層別が要る**。**上がり幅が 1 面ぶん（1/$n$）以内なら分解能**として扱う |
| **C2** | **校正後の安全率は 0.7 より大きい**（0.75〜0.90） | 量 = 判定を満たす最大の安全率。許容差は刻み 0.05 | **= 0.70**（現行が既に最適）／**< 0.70**（**現行が危険側**。**これは重い**）／**> 0.90**（→ F-1 = 物理限界の実測値そのものを疑う） |
| **C3** | **最速タイムは安全率に比例して縮む**（$v \propto$ 安全率） | 量 = 安全率ごとの最速タイム中央値の対数を安全率の対数へ回帰した冪。**予測 −1.0 ± 0.3** | **0 に近い** = 安全率を上げてもタイムが縮まない（**別の律速**）／**−1.3 より急** = 想定外 |
| **C4** | **横偏差の最大は安全率に対して単調に増える** | 量 = 面ごとの $\lvert e_y\rvert$ 最大の中央値 | **非単調** → **F-3**（追従制御が非線形。**曲率不連続 = 016-G が疑わしい**） |
| **C5** | **失敗は特定の面に集中しない** | 量 = 失敗面の集中度（**最初に落ちる 3 面が全失敗の 50% 未満**） | **集中する** → **F-4**。**完走率という 1 つの数で扱うのは不適切**。**面の性質（最小 $R$・連続ターン数）で層別する** |
| **C6** | **0.60 で完走率 100%** | 量 = 安全率 0.60 の完走率 | **100% 未満** → **F-2**: **安全率以外に律速がある**（経路生成・追従制御）。**安全率の校正では解けない** |

### 4-1. F-1（REQ_001）の扱い

**「安全率を上げても完走率が落ちない（0.9 でも 100%）」場合は、
物理限界の実測値そのものを疑う**（$v_\max$=3.86・$a_\max$=5.6・$a_\text{lat}$=5.87 が
保守側に外れている可能性）。**C2 の「> 0.90」の分岐がこれに当たる。**
