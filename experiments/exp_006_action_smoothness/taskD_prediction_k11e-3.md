# 予測の事前登録: 案 3 k = 1.1e-2（閾値の手前で成功確率が崩れるか）

起草: 学生B 2026-08-11 / 状態: **学習を回す前に登録**（`docs/RESEARCH_PLAN.md` §9）

## 1. 目的 — 性能ではなく**枠組みの検証**

M1 の判定基準は k=8.7e-3 で既に満たした（反転 11.6〜14.8 < 必達線 15.4）。
**本実験は性能を追うものではない**（教授裁定 2026-08-11）。検証したいのは次の主張である:

> **k の上限は計算で出る量であり、実験で探る量ではない。**

`taskB_return_ordering.md` は、割引後総収益の順序（ゴール > 最も得な衝突）が崩れる閾値を
**k = 1.23e-2** と算出した。これが本物なら、**閾値へ近づくにつれて成功確率が単調に崩れる**はずである。

これは案 3 の成果のうち**最も一般性が高い**（他のタスクへ持っていける）。

## 2. これまでの実測 — 余裕と成功確率の対応

| k | c = k·0.483 | **余裕** | 成功/試した seed | 反転[回/s] |
|---|---|---|---|---|
| 2.0e-3 | 9.66e-4 | 0.188 | **3 / 3** | 21.3〜29.9 |
| 5.0e-3 | 2.42e-3 | 0.134 | **2 / 2** | 17.3〜20.7 |
| 8.7e-3 | 4.20e-3 | 0.066 | **2 / 3** | 11.6〜14.8 |
| **1.1e-2** | **5.31e-3** | **0.024** | **本実験** | ? |
| 1.23e-2 | 5.94e-3 | 0.001 | （閾値。順序が崩れる） | — |

**余裕が 0.188 → 0.134 → 0.066 と減るにつれ、成功確率が 3/3 → 2/2 → 2/3 と落ちている。**
本実験の余裕 0.024 は **k=8.7e-3 の 36%**、閾値までの残りは **わずか 0.024** である。

## 4. 予測

### P-1. 成功確率（主予測）

**成功は 0〜1 / 3 seed。確信度 中〜高（0.7）。**

根拠: 余裕と成功確率の対応が単調で、本実験の余裕 0.024 は k=8.7e-3（0.066）の 36%。
外挿すれば 1/3 かそれ以下。

**判定**:
- **0〜1 / 3 なら「k の上限は計算で出る」が実測で裏づけられる**
- **2 / 3 以上なら、余裕は成功確率を支配していない**。閾値 1.23e-2 の導出が
  保守的すぎる（＝衝突位置 2.5 m・1.6 m/s の仮定が悲観的すぎる）ことになり、
  `taskB_return_ordering.md` の感度解析をやり直す

### P-2. 成功した seed の反転（副予測）

**成功する seed があれば、反転は 8〜12 回/s。**
外挿: 21.3〜29.9 → 17.3〜20.7 → 11.6〜14.8 と、k を上げるごとに約 4〜6 回/s ずつ下がっている。

**もし成功しても反転が 11.6 を下回らないなら**、罰の効きが飽和したことになり、
**k を上げても滑らかさは買えない**（＝ここが案 3 の到達限界）と分かる。

### P-3. 失敗の様式（副予測）

**失敗するなら衝突。時間切れ率は 0.20 未満。**
根拠: 案 3 は罰の総量が ‖Δa‖² の 1/8 なので、k=1e-3（‖Δa‖²）で見られた
「衝突解と滞留解の往復」（時間切れ率 0.75）ほど強い滞留への圧力は生じないはず。

**もし時間切れが高ければ**、案 3 でも滞留解が誘引されることになり、
`taskB_return_ordering.md` の滞留の総収益（k=1.1e-2 で約 −1.2）が効いていることになる。

### P-4. 外れた場合の解釈をあらかじめ決めておく

- **3/3 で成功したら**: 閾値の導出が保守的すぎた。衝突位置 2.5 m（ゴール直前）を
  「最も得な衝突」として採ったのが厳しすぎる可能性がある。実際の学習では
  ゴール直前で衝突する方策へは到達しにくいのかもしれない。**感度解析をやり直す**
- **0/3 で、かつ余裕が正（0.024 > 0）なのに全滅したら**: 順序が保たれていても
  **到達確率がゼロになる領域がある**ことになる。余裕は必要条件であって十分条件ではない、
  という `taskB_return_ordering.md` §7 の留保が、より強い形で確認される

### 5-2. なぜ外したか — **余裕の大きさは成功確率を支配していなかった**

私は「余裕 0.188 → 0.134 → 0.066 に対し 3/3 → 2/2 → 2/3」という対応を見て、
**余裕が単調に成功確率を決めている**と読み、余裕 0.024 なら 0〜1/3 と外挿した。

**しかし観測は 2/3 で、k=8.7e-3（余裕 0.066）と同じだった。**
余裕が 1/3 に減っても成功確率は動いていない。正しい読みは次のとおり:

> **順序が保たれている範囲（k < 閾値 1.23e-2）では、成功確率に信頼できる劣化は見られない。**
> 2/3 と 3/3 の差は n=3 では統計的に区別できない（Fisher の正確検定で p=1.0）。

**「余裕が小さいほど危ない」は、私が 3 点の対応から読み取った物語であって、
データが支持していたわけではなかった。**k=1e-4（罰がほぼ無い条件）でも 2/3 だったことを
思い出すべきだった — **罰と無関係に 2/3 は起こる**。

**3 点の単調な並びは、4 点目で崩れる程度の証拠でしかない。**

**ただし捨てすぎてもいけない**（2026-08-11 教授指摘）。否定されたのは
「**余裕の大きさが成功確率を決める**」という**量的**な主張であって、
**罰の形による k 依存性の違い**という**質的**な対比はデータがはっきり支持している:

| k の水準 | **‖Δa‖²（exp_006 の旧設計）** | **案 3（高周波成分だけを罰する）** |
|---|---|---|
| 罰ほぼ無し | **3/3**（k=0） | **3/3**（k=2e-3） |
| 中 | **1/3**（k=1e-3） | **2/2**（k=5e-3） |
| 強 | **0/1**（k=1e-2） | **2/3**（k=8.7e-3） |
| さらに強 | — | **2/3**（k=1.1e-2） |

**‖Δa‖² は k とともに 3/3 → 0/1 へ崩れる。案 3 は k を 5.5 倍に振っても 2/3〜3/3 を保つ。**
**この対比が案 3 の存在意義そのものである。**

なお **P(成功|k) という枠組みを持ち込んだのは教授セッション**であり、
3 点を単調と読んだのは指揮側も同じだった。**枠組みの過剰適合は、
指揮側と実務側の両方で起きる。**

### 5-3. 主張の言い直し（教授裁定 2026-08-11）

当初カードに書こうとした「**k の上限は計算で出る量であり、実験で探る量ではない**」は
**正確ではない**。正しくは:

> **計算で出るのは「安全側の下界」であって、真の崖の位置ではない。**
> 閾値 1.23e-2 を下回る k は安全に使えるが、**それを超えたからといって壊れるとは限らない。**

これは弱くなったのではなく**より正確**であり、実用上の価値は変わらない
（安全に選べる k が計算で出るのは有用）。

### 5-4. なぜ計算が保守的になるのか（機構）

`check_return_ordering.py` §6-bis に実装した:

> **「最も得な衝突」は方策の能力に依存する。**その位置まで走れない方策は、そこで
> 衝突できない。学習初期は遠くまで走れないので束縛は始点近くの衝突で決まり、
> 能力が上がるにつれ束縛点が奥へ移動する。
> **静的な最悪ケース（x=2.5 m）は、どの時点の方策にも対応しない仮想的な条件**であり、
> 必然的に保守的（安全側）になる。

到達できる最大距離 $x_\text{max}$ ごとの閾値（案 3、α=0.5）:

| $x_\text{max}$ [m] | 束縛となる衝突 x | 余裕(c=0) | 閾値 k |
|---|---|---|---|
| 0.60 | 0.60 | 1.169 | 2.16e-2 |
| 1.26 | 1.26 | 0.693 | 1.77e-2 |
| 2.00 | 2.00 | 0.361 | 1.40e-2 |
| 2.50（採用＝最厳） | 2.50 | 0.225 | **1.23e-2** |

閾値は $x_\text{max}$ とともに単調に下がる ＝ **能力が上がるほど束縛が厳しくなる**。
ただし $x_\text{max} \to D_0$ ではゴールへ到達でき（ゴール 0.799 > 衝突 2.5 m の 0.574）、
**その領域の方策はもう衝突を選ばない**。つまり最厳ケースは**通過しない状態**を
束縛に採っている。
