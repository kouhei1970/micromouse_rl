## 2. 項目ごとの詳細

### 1. `maze6_eval.py` へ R4 の注意書きと `total_yaw_rad`

- **現状**: `mouse/corridor_eval.py` には R4 の警告コメント（`n_turns` は方式間比較・
  対外報告に使用禁止）と `total_yaw_rad`（リセットなしの総ヨー角）が入っているが、
  **`mouse/maze6_eval.py` には両方とも無い**（`n_turns` の計算だけがある）
- **やること**: `corridor_eval.py` と同じ警告コメントを付け、`total_yaw_rad` を戻り値へ追加
- **検証**: 既存の評価値（ゴール率・衝突率・時間切れ率・オドメトリ誤差・電流）が
  変わらないこと（**新キーの追加のみ**）。検証帯 20 面で改修前後の値を突き合わせる
- **報酬**: 触れない（評価側のみ）

### 2. `n_turns` → `n_turns_reset45`

- **やること**: 名前だけ変える。**計算式は 1 文字も変えない**
- **条件（裁定 R11）**: **旧記録の `n_turns` が同じ量であること**を docstring と
  実験カードに明記する（過去の記録が読めなくならないように）

### 3. シャーシ外形を `params.py` へ

  **コード側の出所は `mouse/robot_v2.py` の文字列リテラルのまま**
- **やること**: `RobotParams` にフィールドを新設し、ビルダーがそれを参照する

- **報酬**: 触れない（幾何の出所の移動のみ）

### 4. (b) の加法項を「区画をまたぐ歩」に限定

$$\lvert\Delta\Phi_t\rvert \le \sqrt2\,\kappa\,\lvert\Delta p_t\rvert + \mu_\max\cdot\mathbb{1}[\text{区画をまたいだ}]$$

- **動機**: 同じ文書の $\kappa$ の導出が既にこの区別をしている（区画内に留まる歩では
  $\kappa=1$ で足りる）。**$\mu_\max$ にも同じ区別を適用して非対称を消す**
- **🔴 注意（AUDIT_010）**: **1 歩で 2 つの境界を跨ぐ場合（隅の通過）は $2\mu_\max$ が要る。
  限定するなら跨いだ枚数で数えること**
- **検証**: 条件 E の 11/11 が**据え置きで PASS** すること（**検査は厳しくなる向き**なので、
  落ちたらそれは実装の欠陥の発見であって、条文を戻す理由にはならない）
- **報酬**: 触れない（**検査の条文**。学習には一切影響しない）

## 3. 実施順・相互依存・検証の切れ目

### 依存関係

```
  (1) maze6_eval に R4 注意書き＋total_yaw_rad
        ↓ 同じファイルを触るので連続で
  (2) n_turns → n_turns_reset45
  ------------------------------ 検証の切れ目 A（評価値の不変を確認）
  (4) (b) の加法項の限定        … tests/ と design.md のみ
  (6) geo_rho → geo_rho_applied … info の鍵のみ
  ------------------------------ 検証の切れ目 B（11/11 と (f) を確認）
  (3) シャーシ外形を params.py へ … XML の SHA 一致が合格条件
  ------------------------------ 検証の切れ目 C（XML バイト一致を確認）
  (8) 規約判定の並記記録        … 記録のみ・軌道 bit 一致が合格条件
  (7) 帯明示＋安全弁            … 担当範囲の確認が先
  ------------------------------ 検証の切れ目 D
  (5) 🔴 post_3_3 の是正        … **単独で最後に**。影響評価つき
```

### 1 実験 1 変更の原則との関係

**本バッチは実験ではなく保守である**（学習を回して結論を出すものではない）。
ただし **「1 コミット 1 変更・変更ごとに検証を挟む」**という同じ規律を適用する:

- **1 項目 = 1 コミット**（パス明示）。複数項目を 1 コミットに混ぜない
- **検証の切れ目**（上図の A〜D）では、**その時点までの変更が数値を動かしていないこと**を
  実測で確認してから次へ進む。**動いた場合は、そこで止めて報告する**
- **項目 5（`post_3_3`）だけは「数値が動くことが分かっている」**ので、
  **単独で最後に**行い、**動いた量を測って報告する**（動かないことの確認ではなく、
  動いた量の記録が成果物になる）
- **項目 3・8 は「動かないことが合格条件」**（XML の SHA 一致・軌道の bit 一致）。
  **合格条件を先に書いてから着手する**

### 中断・再開

各切れ目でコミットするので、**どこで中断しても次の担当が切れ目から再開できる**。
引き継ぎメモには**「どの切れ目まで通したか」**を書く。
