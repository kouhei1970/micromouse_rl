## 1. 仮説

完成した地図から引いた最短経路を**ターン種別の列**として実行し、
連続する直進を 1 つの動作に伸ばして走れば、探索走行より速くゴールに達する。

## 2. 変更点（1 実験 1 変更）

`classic/explorer.py` に最短走行の段階を足した。**速度上限（`DEFAULT_V_CRUISE` 等）は変更しない**
（速度の引き上げは段階 S4 の担当）。速さの源は「区画ごとの停止・整定を n-1 回分省くこと」だけである。

## 3. 対象迷路（結果を見る前に固定する）

`competition/mazes/design_turn_v1/`（ターン種別が満遍なく出る条件で選抜した調整用迷路。
seed 41000 以上。選抜条件は `competition/maze_gen_turnmix.py` の docstring）。

**対象 = `manifest.json` の最短歩数 D0 が小さい順に 6 迷路。同点は seed の小さい順。**

    41001 (D0=52) / 41009 (57) / 41012 (66) / 41005 (75) / 41008 (78) / 41002 (88)

この選び方は走行の結果に一切依存しない（D0 は迷路そのものの性質で、生成時に
`manifest.json` へ記録済み）。

**D0 の小さい順に採る理由**（教授裁定 2026-08-19）: 持ち時間は 420 秒しかない
（`docs/RESEARCH_PLAN.md` §2）。現在の速度上限（0.12 m/s・区画ごと停止）では、
D0 が 100 を超える迷路は探索走行だけで持ち時間を使い切る見込みが高い。
本実験が判定したいのは「最短走行が探索走行より速いか」であって
「長い迷路でも探索が終わるか」ではない（後者は段階 S1 の話である）。
探索が持ち時間で切れる迷路では S3 を測ることそのものができないため、
測定が成り立つ規模へ寄せる。**この偏りは §11 の限界 2 に明記する。**

### 生成器の選抜条件についての裁定（2026-08-19・結果を見る前に記録する）

1. **条件「連続ターン（間に直進を挟まない隣り合うターン）」の読み替えを承認する。**
   格子の上ではターンとターンの間に必ず 1 区画以上の移動が入るため、字義どおりでは
   決して成立しない条件だった（seed 41000〜41059 の 60 迷路で実測 0 件）。
   「**間の直進が 1 区画だけの隣り合うターン**（＝加速する余地の無いつづら折れ）」と読み替える。
   実機で難しいのはまさにこの箇所であり、読み替えは元の意図に一致する。
2. **選抜条件はこのまま据え置く**（強めない）。D0 窓 [45, 110] を満たす候補の
   実測 200 件すべてが 4 条件を通過した。これは「ふるいが甘い」のではなく、
   **S3 が使う性質（右左のターンが両方出る・長い直線がある・加速余地の無い連続ターンがある）は
   この規模の迷路にほぼ必ず現れる**という測定結果である。したがって S3 については
   専用の選抜を強める必要が無い。`note_030` §4 の表のうち「ターンの検証」の行は
   この実測をもって解決とする。斜め（S5）の検証用迷路では選抜力が要るはずなので、
   そこで改めて設計する。
3. 各迷路のターン種別の内訳は `manifest.json` に記録済みであり、判定文書に添える。

## 4. 一次記録

1 迷路 × 1 条件につき 1 ファイル。
`outputs/exp_024_s3/<condition>/maze_<seed>.json` に、
`competition/evaluator.py` の `evaluate_maze()` が返した辞書をそのまま保存する。
併せて次の 2 つを同じ辞書に足す（走行の一次記録であり、集約値ではない）:

- `plan_ids`: ティックごとの計画識別子の列（`ClassicExplorerPolicy.get_plan_ids()`）
- `run_phases`: 走行が始まった瞬間の段階の列（`[{"run_index": 1, "phase": "EXPLORE"}, ...]`）

条件は 2 つ:
- `extended`: 直線を伸ばす（`extend_straights=True`。本命の構成）
- `percell`: 直線を伸ばさない（`extend_straights=False`。経路も地図も同じで、延伸だけを外した対照）

## 5. 用語の定義（判定に使う量の出どころ）

- **探索走行のタイム** `T_explore(i)`
  = 迷路 i で**最初にゴールした走行**のタイム。`docs/RESEARCH_PLAN.md` §2 の
  「探索走行」の定義（2026-08-13 裁定 R22）に一致する。
- **最短走行のタイム** `T_fast(i)`
  = 迷路 i で「**走行が始まった瞬間の段階が FAST であり、かつゴールした走行**」の
  タイムの最小値。該当する走行が無ければ未定義とする。
  🔴 「最初のゴール走行より後」という順序だけで決めない。探索が 1 往復で終わらず
  2 回目の探索走行がゴールする場合があり、それを最短走行と数えると量が濁るため。
- タイムは評価器が返す `runs[].run_time`（秒）をそのまま使う。丸めない。
  ゴール区画内での停止確認に要した時間はタイムに含まれない（評価器の規約）。

## 6. 主判定量（1 つの実数・実数直線を切れ目なく分割する）

    S  = 対象 6 迷路のうち、条件 extended で T_fast(i) が定義される迷路の集合
    R  = max( T_fast(i) / T_explore(i) )   （i ∈ S）
    S が空集合のときは R = +∞ と定める。

**判定**:

| R の範囲 | 判定 |
|---|---|
| `R < 1.0` | **合格** |
| `R >= 1.0`（+∞ を含む） | **不合格** |

- 同値の扱い: `R = 1.0` ちょうどは**不合格**側に入れる。
- 許容差: 設けない（秒の実数をそのまま比較する）。
- 最大値を採るのは、出口条件が「専用迷路で完走し、探索より速い」であり、
  走った迷路のどれか 1 つでも遅ければ出口条件を満たさないため。
  🔴 合計・平均で語らない（`handover/professor.md`「件数は少数の迷路に支配される」）。

**予測**: `R` は 0.2〜0.6 に入る。
根拠: 探索走行は袋小路を含む往路と、区画ごとの停止・整定（1 区画あたり実測で約 0.3 秒の空費）を
伴う。最短走行はそのどちらも無い。

## 7. 副判定量（2 つ以内）

### 副 1: 最短走行の成立率

    C = |S| / 6

**予測**: `C >= 0.5`。
根拠: 現況の探索到達率は調整用迷路（`design_v4`）3 迷路中 2 迷路（`handover/professor.md`）。

### 副 2: 直線延伸の寄与

    S' = 条件 extended と条件 percell の両方で T_fast(i) が定義される迷路の集合
    E  = median( T_fast_extended(i) / T_fast_percell(i) )   （i ∈ S'）
    S' が空集合のときは E = +∞ と定める。

**予測**: `E < 1.0`。
`E >= 1.0` なら「直線を伸ばす」は速さに寄与していない（S3 の中身が空だったことになる）。

## 8. 段階 S3 完了の宣言条件（主判定量とは別に、ここで明示する）

**主判定 `R < 1.0` かつ 副 1 `C >= 0.5` の両方**を満たしたときにのみ、S3 完了を宣言する。
🔴 これは主判定量の中に連言を入れないための書き分けである（§12-9 (c) の但し書き）。
主判定量はあくまで実数 `R` 一つであり、宣言の条件だけが 2 つある。

欠けた場合の読み方も先に決めておく:

| 結果 | 記録すべき読み方・次の仕事 |
|---|---|
| `R < 1.0` かつ `C >= 0.5` | S3 完了。次は S4（速度向上） |
| `R < 1.0` かつ `C < 0.5` | 不足は S3 ではなく **S1（探索の到達率）**。次の仕事を到達率へ向ける |
| `R >= 1.0`（S が空でない） | S3 の実装に不足がある。最短走行が探索より遅い原因を一次記録から切り分ける |
| `R = +∞`（S が空） | 最短走行が 1 本も成立していない。まず成立しない原因（探索未完了か、最短走行の実行時の失敗か）を `run_phases` と `outcome` で切り分ける |

## 11. 限界（5 個以内）

1. 有効標本は迷路の数（6）である。**走行の水準で p 値を計算して条件比較に使わない。**
2. 対象は調整用迷路（seed 41000〜）であり、検証用・評価用の迷路での成績ではない。
   さらに **D0 の小さい順に 6 迷路を採っているので、規模の小さい側へ偏っている**（§3）。
   本実験の合格は「持ち時間内に探索が終わる規模の迷路で、最短走行が探索より速い」までしか
   主張しない。段階の完了確認としてはここまでで、章の完了確認では検証用迷路を使う。
3. 探索が完了しない迷路では最短走行がそもそも始まらない。主判定量は成立した迷路だけを見る
   （覆いは副判定量 1 が受け持つ）。
4. 速度上限は S1 のまま（0.12 m/s）。理想タイム（物理限界からの下界、`research_notes/note_025` §2-0）
   との比較は S4 以降でなければ意味を持たない。**本実験で理想タイムとの比を判定に使わない。**
5. 最短走行中は地図を書き換えない設計のため、探索で誤った地図を作った迷路では衝突しうる。
   これは設計どおりの振る舞いであり、`outcome` が `collision` になることで一次記録に残る。

## 追記 1: 投入前の検収で見つかった不足への裁定（2026-08-19・**測定を 1 本も走らせる前**）

反証的な検収（4 つの視点）を実装 `059e7cd` にかけ、次の 6 件を是正することにした。
🔴 **いずれも判定条文（§6・§7・§8）を変えるものではない。**測定はまだ 1 本も走らせていない。

| # | 見つかったこと | 裁定 |
|---|---|---|
| 1 | ゴール到達後の静止 0.2 秒は、評価器が「機体全体がゴール区画に入り速度 < 0.02 m/s」を確認し終える時刻との余裕が**実測 0.2 秒しかなかった**（確認完了は前端通過から 1.33 秒、機体停止は 1.3 秒）。停止位置が少しずれると走行が `goal_not_contained` で失われる | `GOAL_STOP_HOLD_S` を **0.2 → 2.0 秒**へ。評価器の上限は 5.0 秒なので余裕がある。走行タイムは前端通過で確定するので**タイムには影響しない** |
| 2 | 「最短走行中は地図を書き換えない」という裁定を**破っても検査が 1 件も落ちなかった**（検査用の迷路が単純すぎて、書いても内容が変わらなかった） | 内容の一致ではなく**呼び出しの配線**を検査する。作動側・空振り側を対で置く |
| 3 | 最短走行の異常時の安全弁 `fast:blocked` を**作動させる検査が無い** | 作動側・空振り側を対で置く |
| 4 | 最短走行の検査が競技評価器を一度も通っていない（2 段階のゴール判定を素通りしている） | 実際の迷路を評価器で走らせ、最短走行が `goal` で成立し `goal_not_contained` が出ないことを検査する |
| 5 | 用語辞書の禁止語「発火」が新規記述 2 箇所に入っていた | 辞書どおり「作動」へ直す |
| 6 | 最短走行のあとスタートへ戻る帰路が、地図が完成しているのに**足立法で 1 区画ずつ止まりながら**走っていた。実測で maze_41001（最短歩数 52）の持ち時間 420 秒のうち、帰路だけで 80 秒以上を消費し 3 本目の走行が始まらなかった | 帰路も**完成した地図から最短経路を引き、直線を伸ばして**走る。実機も帰路は速く戻る。`note_030` §2 の L4「最短走行 ×N」が成立するための前提でもある |

**6 について**: これは「合格しやすくするための調整」ではなく、**設計の不足の是正**である。
帰路の所要時間は判定量 `R`・`E` に一切入らない（タイムはスタート区画を出てからゴールまでしか計らない）。
影響するのは副判定量 `C`（最短走行が成立するかどうか）だけであり、
「地図が完成しているのに探索と同じ走り方で帰る」ことに設計上の根拠が無い以上、
測定の前に直すのが筋である。**直したことと理由をここに残す。**

**探索が完了する前の帰還（`Phase.RETURN`）は変えない。**そちらは地図が未完成なので、
足立法で 1 区画ずつ確かめながら戻るのが正しい。
