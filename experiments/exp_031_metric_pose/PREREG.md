## 1. 何を変えるか（1 実験 1 変更）

連続の姿勢 $(x, y, \theta)$ を推測航法で積分する推定器を新設し、**走行に並走させて誤差を記録する**。

- 制御には一切使わない。既存の走行経路には触れない
- 状態は $(x, y, \theta)$ の 3 つだけ。ジャイロバイアスは E2 で足す
- 観測による更新は入れない。予測だけ

変えないもの: `classic/explorer.py`・`classic/motion.py`・`classic/tracker.py`・
`classic/sensing.py`・`classic/maze_map.py`・`classic/localization.py` の挙動。

## 2. 主判定量（1 つの実数）

**区画取り違え率**

$$r_{cell} = \frac{\text{推定姿勢から決まる区画が真の区画と異なった制御ティックの数}}{\text{探索走行の全制御ティック数}}$$

$r_{cell} \in [0, 1]$。区画は $\lfloor x/0.18 \rfloor,\ \lfloor y/0.18 \rfloor$ で決める（境界は下側を含む）。
真の区画は `MouseSim.privileged_pose()` から同じ式で決める。**真値は診断だけに使い、推定器へは渡さない。**

対象: `competition/mazes/design_v4/` の 10 迷路（古典の設計帯 seed 41000〜61000。
評価帯・検証帯の候補プール [1000, 40999] は使わない）。**10 迷路の $r_{cell}$ の中央値**を報告する。

### 実数直線の分割（切れ目なし・連言なし）

| 中央値 $r_{cell}$ | 読み |
|---|---|
| $[0,\ 0.05)$ | 推測航法だけで区画をほぼ取り違えない。**補正の必要性そのものを問い直す。**まず測定系が真値を漏らしていないかを疑う |
| $[0.05,\ 1]$ | 補正が要る。E2 以降へ進む |

### 事前の予測

**中央値は 0.05 以上になる。**理由: 車輪の滑りは模擬に実在し（`classic/localization.py` の
冒頭が記録している maze_41038 の 10 区画直進で横方向 26〜28mm の蓄積）、
縦方向の誤差には上限を与えるものが何も無いため。

## 3. 合格条件（測定系の健全性・すべて満たすこと）

判定量の値とは別に、測定系が働いていることを次で確かめる。

1. **走行が変わらない**: 推定器を付けた走行と付けない走行で、結果 JSON の SHA-256 が一致する
2. **否定対照 N1・N2 が両方発火する**（§4）
3. **錨の独立再計算が集計値と一致する**（§5）

いずれかを満たさない場合、$r_{cell}$ の値は判定に使わない。

## 4. 否定対照

| # | 壊すもの | 発火の条件（これを満たさなければ、その経路は使われていない） |
|---|---|---|
| N1 | 推定器に渡す車輪角速度を 0 に固定 | 推定位置の総移動距離が 1 mm 未満にとどまる |
| N2 | 推定器に渡すジャイロ $\omega_z$ を 0 に固定 | 方位誤差の RMS が、壊す前の 3 倍以上になる |

しきい値の 3 倍は暫定である。**空振りの分布を先に測り、両対照の実測値を見てから確定させる**
（`RESEARCH_PLAN` §12-9「閾値は対照で校正する」）。校正の記録は本カードに追記する。

## 5. 錨の独立再計算

`experiments/exp_031_metric_pose/anchor_check.py` を、集計スクリプトとは独立に書く。

- 走行の一次記録（ティックごとの推定姿勢と真値姿勢の生ログ）だけを入力に取る
- $r_{cell}$ を自分で数え直し、集計結果と照合する
- 集計スクリプトの出力は読まない
