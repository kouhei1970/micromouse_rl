# exp_036 事前登録: 走行ライン — 折れ線の角を丸める

- 日付: 2026-08-23（結果を見る前に凍結）
- 起票: 教授セッション／規約 `docs/RESEARCH_PLAN.md` §12-9
- 根拠: `note_037` §16（ユーザ指示 2026-08-23）／`exp_032`（柱間グラフ）／`note_029`

## 1. 何を作るか

`classic/gap_graph.py` が返す**折れ線**（頂点＝柱間の中点、線分＝0.09・0.127・0.180 m、
向き＝0°・±45°・90°・±135°・180°）の角を丸めて、**連続した走行ライン**にする。

出力は弧長で表した $(s,\ \kappa(s))$ の格子。既存の `classic/profile.py` の `min_time()` が
そのまま受け取れる形にする（`note_037` §16-2 の 2 番目）。**走行はしない。純計算。**

🔴 **丸め方が曲率を決め、曲率が速度を決める。**ここが最適化の場所である。

## 2. 主判定量（1 つの実数）

$$\tau = \frac{\text{丸めた走行ラインの理想時間}}{\text{従来のターン種別の列の理想時間}}$$

同じ迷路・同じ発進・同じゴールで、`classic/profile.py` の `min_time()` に通して比べる。
対象は `competition/mazes/design_v4/` の 20 迷路。**中央値**を報告する。

| $\tau$ | 読み |
|---|---|
| $[0,\ 0.90)$ | 想定より大きく速くなった。**まず実装の誤りを疑う**（§3 の余裕を再確認） |
| $[0.90,\ 1.00)$ | 速くなる。斜めを採る根拠になる |
| $[1.00,\ \infty)$ | 速くならない。`note_029` の再来。丸め方を見直す |

### 事前の予測

**$\tau \in [0.90,\ 1.00)$。**距離は `exp_032` で 0.818 倍に縮むと測れているが、
斜めは曲率が付くぶん速度上限が下がる。**距離の比ほどは縮まない。**

🔴 `note_029` は、旧実装の斜めが**対照より 18.6% 遅かった**と記録している。
本実験はその問いに正面から答えるものである。**遅いなら遅いと報告する。**

## 3. 合格条件（すべて満たすこと。満たさなければ判定に使わない）

🔴 **壁を削れば速くなってしまう。**次で塞ぐ。

1. **すべての迷路・すべての弧長で機体の余裕が正であること**（`classic/geometry.py` の
   干渉判定。余裕の最小値を迷路ごとに報告する）
2. **曲率が連続であること**（不連続だと追従できない。$\kappa$ の跳びの最大値を報告する）
3. 否定対照 3 つが発火すること（§4）
4. 錨の独立再計算が集計と一致すること

## 4. 否定対照

| # | 壊すもの | 発火の条件 |
|---|---|---|
| N1 | 丸めを行わず折れ線のまま `min_time()` に通す | 理想時間が悪化する（角で止まることになる） |
| N2 | 余裕の判定を外して角を深く丸める | 余裕の最小値が負になる（合格条件 1 が実際に効くことの確認） |
| N3 | 斜めを禁じた折れ線で同じ処理を通す | $\tau$ が 1 に近づく（斜めが速さの源であることの確認） |

**しきい値は置かない。**実測値を並べて報告する。

## 5. 錨の独立再計算

一次記録（迷路ごとの $\kappa(s)$ 格子・理想時間・余裕の最小値）だけから $\tau$ の中央値と
余裕の最小値を数え直し、集計と照合する。`run.py` を読まない。

## 6. マイコン実装の予算（`note_037` §13-4）

折れ線 1 本を走行ラインへ変換する演算量と RAM。**1 kHz の制御周期に収まるか、
走行を止めて計算する必要があるか**（`exp_032` のダイクストラ法は 5 ms で収まらなかった）。

## 7. 副次の記録（判定には使わない）

曲率の最大値と、それが機体の限界に対してどこにあるか／斜め区間の割合／
丸めた結果の経路長（折れ線からどれだけ短くなったか）／
理想時間の内訳（直線・弧・斜め）。
