# 検証迷路（現行・**v4**。2026-08-12 凍結）

**日常の実験判断に使う帯**（ハイパーパラメータ選択・実験の合否見込み・学習の打ち切り
判断はすべてこちらで行う。研究計画書 §9-7）。候補プール **seed 21000〜40999** から
選抜した 20 面。生成器は `competition/maze_gen_v3.py`。

対になる評価帯は `competition/mazes/eval/`（候補プール **seed 1000〜20999**）。

## 評価帯との対応関係

**受理条件は評価帯と完全に同一**である。違うのは**候補プールの seed 範囲だけ**。

| | 評価帯 `eval/` | 検証帯 `validation/`（本帯） |
|---|---|---|
| 候補プール | seed **1000〜20999** | seed **21000〜40999** |
| 受理条件 | 規定 6 項目 ＋ $D$ 窓 [45,110] ＋ $R$ 層別（4 層 × 5 面）＋ $K$ 階級 {4,8,8} | **同一** |
| $\Delta$ / $\theta$ | 4 / 3（凍結） | **同一** |
| 除去枚数 | 15 | **同一** |
| 消費 seed | 13038 | 4843 |
| 規定通過の候補 | 5435 面 | 2054 面 |
| 採用 seed | 1018〜14037 | 21003〜25842 |

**プールは重ならない**（[1000, 20999] と [21000, 40999]）。したがって
**同じ迷路が両帯に現れることはない。**

受理条件・選抜の位置づけ（最大化ではなく分布一致）・限界 3 点の説明は、
**`competition/mazes/eval/README.md` を正とする。**ここでは重複させない。

## 再現性・凍結記録

- **層ごとの受理率**: 層1 0.7%（5 / 724）／層2 4.0%（5 / 124）／層3 7.0%（5 / 71）／層4 7.7%（5 / 65）
  - ⚠️ **この受理率を帯どうしで比べないこと。**受理率の分母は「打ち切りまでにその層で
    見た候補数」で、層別サンプリングは全層が埋まった時点で打ち切る。**最後の 1 面が
    出るまでの運で分母が変わる**（評価帯は最後の $K\geq3$ の 1 面に seed 14037 まで
    かかったので分母が大きく、受理率が低く見える）。**帯の性質ではない。**
- `manifest.json` に候補全数 4843 件の採否を記録
- `freeze_record.json` に npz / XML の SHA-256
- `rule_audit.json` に規定適合の検査結果

再現コマンド:
```bash
.venv/bin/python -u -m competition.maze_gen_v3 --out-dir <出力先> \
    --seed-from 21000 --seed-to 40999 --extra-open 15
```

## 経緯

| 版 | 場所 | 退役理由 |
|---|---|---|
| v2-short | `validation_v2_short/` | 経路が短すぎた |
| v2 | `validation_v2_low_detour/` | 探索の遠回りが小さすぎた |
| v3 | `validation_v3_low_k/` | 候補経路が少なかった（$K$ 中央値 1.0） |
| **v4（本帯）** | **`validation/`** | — |

> **seed 帯の変更について**: v3 までの検証帯は候補プール seed 4000 台を使っていたが、
> **v4 では評価帯の候補プール [1000, 20999] と重ならないよう 21000 台へ移した。**
> 生成器 v3 は 1 面あたり多数の seed を消費するため、旧来の「検証 = 4000〜4019」
> という 1 面 1 seed 前提の割り当てでは、**評価帯の候補プールと重複する**。
> 研究計画書 §9-7 の記述との対応は**教授が正本を改訂する**（学生A から報告済み）。
