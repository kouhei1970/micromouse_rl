## 1. 完成の定義（案・要ユーザ合意）

**「古典の完成」= 特権情報（シミュレータの真値）を使わず、実機と同じ情報だけで探索から最短走行までを行い、真値走行に迫る性能を出すこと。**

- **範囲（教授の推奨案）**: 探索走行（壁の検出・地図作成）と最短走行の**両方**をセンサベース化する。理由: 実機同等が裁定の趣旨であり、RL との比較（同じセンサ入力同士）も初めて対等になる。
- **迷路の帯の使い分け（教授裁定 2026-08-15・3 段）**:
  1. **開発・カード単位の判定 = 設計帯**（`competition/mazes/design_v4/`・seed 41000〜の 20 迷路）。016 系の従来判定（v_斜め の速度引き上げ試験の過去値 0.40/0.45 を含む）との同一迷路比較を保つ
  2. **章の完了確認 = 検証帯**（`competition/mazes/validation/` の 20 迷路）。設計帯への合わせ込み（過適合）の検出 — 設計帯で出た利得が検証帯でも保たれることを章の出口条件とする
  3. **最終の完成判定 = 評価帯**（`competition/mazes/eval/` の 20 迷路）。マイルストーン判定として一括（`RESEARCH_PLAN` §9-7）
- **合格基準（最終判定 = 評価帯で測る）**: (a) 探索→最短走行の全手順をセンサのみで完走 20/20、(b) **最短走行のタイムが、物理限界から計算した理想タイム（第 0 章）に対し一定倍率以内**（倍率は理想計算とシミュレーション実測の突き合わせ後に根拠つきで確定）、(c) 経路単位の斜めあり/なし選択が動作し、斜めを選んだ迷路で実測利得。
  - **🔴 [ユーザ裁定 2026-08-15] タイムの基準に現行制御の真値走行タイムを使わない**（「当てにならない制御を基準にして良し悪しを決めない」）。基準は**車両の物理限界（モータ性能・タイヤ摩擦・加減速とコーナリングの限界）から計算で導く理想タイム**とする。まずサーキット（16×16 の外周周回課題）で理想値を計算し実測と突き合わせて計算の妥当性を確立する
  - 訂正 2026-08-15（2 回）: 初版は誤って 6×6 の検証帯（seed 7000〜7019）を記載 → 是正。第 2 版は設計帯の存在を見落とし「各章の判定 = 検証帯」と書き 016 系の連続性を壊すところだった（いずれも学生A の異議 → 教授裁定で是正）。
  - 合意済み（ユーザ・2026-08-15）: 範囲 = **探索もセンサ化する**／v_斜め = **上限・到達目標を設けない**（実測で決まる値を記録し経路単位選択に委ねる）

## 3. 検証の設計（准教授と合意済みの骨子）

- **否定対照を必須とする**: 「真値を意図的に壊した対照 — 壊しても走行が変わらなければ、その経路は真値を使っていない」（exp_023 の L6-b と同型・准教授が設計時に先行登録）。特権情報の残留は数値照合では検出できないため、これが特権除去の実証手段。

- 判定は §12 の規律（事前登録・独立再計算・カード 200 行以内・監査は定点 2 回）。
