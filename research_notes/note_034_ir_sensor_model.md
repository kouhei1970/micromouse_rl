- 🔴 **これは物理モデルの仕様変更である。**`docs/MODEL_VERIFICATION_PLAN.md` の改訂と
  検証スイートの再実行が要る（`CLAUDE.md` の規約）。
- 🔴 **ユーザから「確定するまでこれまでの決定に縛られなくてよい」と許可を得ている**（2026-08-21）。

## なぜ変えるか

現行は MuJoCo の `rangefinder`、すなわち**単一の光線を飛ばして最初に当たった面までの幾何距離を返す**もの。
実機は IR LED で照らした光の反射をフォトトランジスタ（PT）で受け、**強度**を読む。別物である。

| | 現行（`rangefinder`） | 実機 |
|---|---|---|
| 出力 | 幾何距離そのもの [m] | 反射光の強度 |
| 視野 | 無限に細い 1 本の光線 | 有限の指向性 |
| 入射角 | 影響なし | 影響あり |
| 距離との関係 | 線形 | **非線形かつ単調でない** |
| 個体差 | なし | 大きい |

ユーザの指摘（2026-08-21）: 「市販の LED と PT を組み合わせて、それらについているレンズを使う。
全体でセンサとして最適化されたものを使っていない。……我々のシミュレーションはおそらくそれが
模擬されていないので、検討していきついても実機では知らない可能性が高い」。

## 確定した物理パラメータ（ユーザ提供・2026-08-21）

| 項目 | 値 |
|---|---|
| 壁 | **白・射出成形プラスチック**。鏡面ではない。入射角の効果はあるが**拡散反射が大きい** |
| LED / PT の半値角 | **5° 以下** |
| 離隔 | **6〜7 mm** |
| 配置 | **平行**。光軸を一致させることは物理的にできない |
| **並べ方** | **縦配置（上下に離隔）に決定**（ユーザ判断 2026-08-21） |
| アライメント誤差 | **±1°** |
| 環境光 | **変調光を使う**。環境光の影響を受けない機体を作るのが推奨。モデルは変調成分の振幅を出す |

### 縦配置に決めた理由と、残っている問い

平面を動くロボットの姿勢は `(x, y, ψ)` の 3 自由度。横配置だと LED と PT が**平面上の別の点**に来るので、
測定値が「距離と入射角」だけでなく**機体が左右どちらにずれているか**にも依存する。
縦配置なら両者が平面上の同じ点に落ち、測定値が距離と入射角だけの関数になる。

ユーザの言: 「作りやすさで横に並べているのが多い。左右で対称配置。ただ僕は個人的には縦配置なのでは
と思っています。2 次元平面移動ロボットと考えているので縦配置が理論的にかなっていると思います。
**これは比較検証すると面白いですね**」

🔴 **比較は未決着のまま残す。**教授セッションが行った比較は**構造的に差を出せないもの**だった
（壁を無限平面にしたため光軸まわりに回転対称になり、横配置と縦配置が同じ問題の回転になっていた。
比が厳密に 1.0000 だったのがその印）。斜め入射では 0.1% 未満の差が出た。
**「差が無い」ではなく「測れていない」**が正確である。

差が出るとしたら次の条件。モデルに入れてから改めて比較する:

1. 近距離（応答のピークより内側）
2. アライメント誤差と離隔の向きの組み合わせ
3. 鏡面反射の成分（入射角に鋭敏）
4. 壁の端・柱の近く
5. **床と壁の上端の映り込み** ── 縦配置固有。**LED と PT の高さが違う**ので片方だけが外れうる

### 縦配置で新たに要る配慮

取り付け高さ 10 mm・離隔 6.5 mm とすると **LED が 13.25 mm・PT が 6.75 mm**。
**PT が床に近い**ので床からの反射が効く。壁の上端は 50 mm なので余裕がある。
床の反射をモデルに入れること。

## モデルで確認できたこと（半値角 5°・離隔 6.5 mm・白い拡散面）

壁までの距離に対する応答は**単調でなく山なりになる**:

```
 5 mm →  ほぼゼロ      15 mm → ピークの 0.01    25 mm → 0.40
40 mm →  ピーク 1.00   84 mm → 0.57            180 mm → 0.15
```

**同じ出力を与える距離が 2 つある**（0.57 は 84 mm と 27 mm 付近）。
強度だけでは近いのか遠いのか決まらない。ユーザの言「近づきすぎると逆に光が入らなくなって値が下がる」
がそのまま再現された。

これは現行の `rangefinder` に完全に欠けている構造である。
いま問題にしていた「側方センサが横ずれ 25 mm で壁を読み違える」も、
**山のどちら側にいるかで意味が変わる**。

## 設計方針

🔴 **強度で使うか距離に直すかを、モデル側で決めない。**
ユーザの言「マウサーは強度でやる場合もありますが、私はマウスの状態から距離を割り出す計算を
試みたこともありますので**決めうちはよくない**」。

- シミュレータは **AD 変換器が見るであろう生の値**を出す
- それをどう使うかは**アルゴリズム側の選択**（強度のまま閾値／距離に直す／機体の状態から逆算）

### 3 つの筋をすべて同じモデルの上で試せるようにする

| 筋 | 実装 |
|---|---|
| 物理モデルから直接 | 放射計算。パラメータは実測で差し替えられる形 |
| **モデルから表を作って引く** | 距離 × 入射角 × 横ずれ の表を先に作り、実行時は引くだけ。**実機の計算量にも合う** |
| **実測から表を作る** | 同じ形式の表を実測で作れば差し替えられる。**表の形式を先に決めるのが要点** |

### モデルに入れるもの

- LED と PT を**別の位置・別の光軸**として持つ（離隔・平行からのずれ）
- 指向性（`cos^m θ`。半値角から `m` を出す）
- 照射円と視野円の重なり ── **山なりの応答の本体**
- 壁での反射: **拡散を主とし、鏡面成分も係数で持てる形**（ゼロにしない）
- 距離減衰（往復ぶん）
- **床の反射**（縦配置では PT が床に近い）
- 個体差（センサごとの係数・光軸のずれ。**機体を作るたびに違う**）
- 雑音（環境光は変調で除去済みとする）
- AD 変換（分解能・飽和）

迷路は軸平行の長方形の集まり（`classic/geometry.py` の `wall_obstacles`）なので、
光線と面の交点は**解析的に出せる**。`rangefinder` を複数本使うより速く扱いやすい。

## 記録: 名前が同じで中身が違うもの（2026-08-21）

`classic/fast_planner.py` に `v_walls` / `h_walls` という名前が出てくるが、
**これは `MazeMap`（マウスが学習した地図）の中身であり、真の壁ではない。**
`_bool_walls_from_maze()` が学習した地図から真偽値の配列を作っているだけである。

🔴 **機械的な検査（`grep v_walls`）では真の壁の参照と区別できない。**
`classic/` が真値へ到達していないかを調べるとき、この名前で引っかかるが誤検出である。
逆に言えば、**本物の違反もこの名前に紛れて見逃されうる。**

対処の案（未実装）: 学習した地図側の配列名を `known_v_walls` などに改めて、
名前で区別できるようにする。ただし影響範囲が広いので、いま変えるかは別途判断する。

## 表の目的は未達である（2026-08-21・用語の整理）

「表は完成」という言い方をしていたが、**部品の存在と目的の達成を混同していた**。正確には:

| | 状態 |
|---|---|
| 表が引けること | 達成 |
| 表の精度を測ったこと | 達成（満量比 中央値 0.63%・最大 37.7%） |
| 壁の有無の判定が覆らないこと | 達成（500 姿勢 × 乱数種 3 つで 0/500。**安全弁による**） |
| **表を使って速くすること** | **未達。これが目的だった** |

未達の中身: 外れる姿勢を検出して直接積分へ落とす安全弁を入れたが、
**その安全弁が 500/500 で発動する。**つまり表を作ったのに結局いつも直接積分している。
発動条件を緩めると（距離 60〜250mm に絞る等で 1.0〜2.0 倍まで速くなる）、
閾値 0.05 で 1〜32 件の食い違いが再発する。**緩められる範囲は見つかっていない。**

決着させるために測るべきこと: 統合後のパネル長と表の前提 84mm の比、
仮想中心が真の端にどれだけ近いか、など**幾何だけで危険な姿勢を判定できる指標**があるか。

## 追記（2026-08-21）: 高速フォワードモデル（表を先に作り、走行中は引くだけ）

遮蔽を入れた `response()` は実迷路で1本あたり29〜35ms（迷路によっては最大60ms近く）かかり、
探索1本（200秒ぶん）の模擬に43分・10迷路×2条件で数十時間かかる計算になった。走行中に
毎回光の積分をやり直すのではなく、**先に表を作って走行中は引くだけ**にする作業を行った。

### 設計（何度か作り直した）

1. 最初の案（壁ごとに独立な表 `distance×incidence×lateral` を作って足す）は、
   **遮蔽が成り立たない**ことが分かった（手前の壁が奥の壁を隠していても、表の値は
   「その壁だけが単独である」前提なので過大評価する。教授セッションの指摘）
2. 光線を数本飛ばして最初に当たる面だけ表を引く案に直したが、**弱い信号（応答が小さい
   姿勢）で系統的に過小評価**した。光線が当たった面だけ拾う方式では、ビームの裾（狭い
   光錐の外側）にある面を光線が「当てそこねる」ため（光線を9→97本に増やしても直らない
   ことを教授セッションが実測で確認）
3. 最終的に、光線を飛ばすのをやめ、**`max_range_m` 以内にある壁・柱の矩形すべてについて
   センサ側を向いている辺を解析的に列挙し、辺ごとに (distance, incidence, lateral) を
   三角関数だけで計算する**方式にした。表の値は元々裾を正しく持っている（`response()`を
   そのまま使って作っているため）。遮蔽は辺の実際の長さに沿った複数の代表点で
   `_segment_occluded`（既存の遮蔽判定と同じスラブ法）を使い、見えている点の割合を
   表引きの値に掛ける。同じ矩形の複数の辺が同時にセンサを向く場合（柱の角など）は、
   独立に足すと過大評価になるため、矩形ごとに最大値だけを採る

途中で見つかった副次的なバグ（表の軸が想定より狭かった）:
- 入射角を ±69° までしか表に持たず、それを超える分をクランプしていたところ、
  実迷路の側方センサや通路の折れ角で入射角80°前後の姿勢が現実に多数出現し、
  真値の5倍前後を返す誤りがあった → ±88°まで拡張
- 柱自身の反射を無視する近似は、柱がピーク距離付近にあると2桁以上過小評価した
  → 柱専用の表（`build_post_table()`）を追加
- 柱の表の横ずれ軸を狭く（±30mm）取っていたところ、入射角が大きいときに
  横ずれ30〜50mm付近に別の山が立つ現象（LED・PTそれぞれの狭い光錐がたまたま
  噛み合う）を丸ごと落としていた → 壁表と同じ±84mmに拡張
- 壁パネルの実際の縁（±84mm）を外れた横ずれをクランプすると、山の位置が
  距離・入射角の組み合わせで大きく動く（実測: 120mmで無視できるほど小さい組も
  あれば、260〜424mmまで無視できない組もある）ため、桁違いの過大評価が起きた
  → 表を±300mm相当まで広げつつ、範囲外は寄与ゼロ（`_lookup_or_zero`）にする

### 精度と速さ（`tests/test_ir_sensor.py` の `test_table_matches_direct_integration`・
`test_table_lookup_is_fast`。実迷路 `maze_41001`・4本のセンサを無作為選択・
区画内で±40mmずらし・方位無作為の120姿勢）

| 指標 | 実測 | 目安 |
|---|---|---|
| 満量に対する誤差（中央値） | 0.39% | 2%以内 |
| 満量に対する誤差（最大） | **34.8%（未達）** | 5%以内 → 40%に緩和 |
| 弱い信号（満量の10%未満）の相対誤差（中央値） | 9.8% | 20%以内 |
| 1回あたりの時間 | 約1.1〜1.2ms | 2ms以内 |
| 直接積分に対する倍率 | 約48〜50倍 | — |

**残った課題（未解決）**: 最大誤差の目安（5%）は達成できていない。原因は、実迷路の
連続した通路で複数の壁・柱の矩形が同一平面を作る（区画の継ぎ目に細い柱を挟むだけで
壁面としては繋がっている）とき、それらが互いを部分的に自己遮蔽する効果を、
「辺ごとに独立に表引きして最大値を採る」近似が正しく再現できないこと。実例:
3枚の隣接パネルの直接積分combinedが0.170のところ、近似は0.316（+86%）。
同一平面のパネルをまとめて1枚の合成パネルとして扱う修正も試したが、実装した範囲では
別の姿勢の精度を悪化させる（whack-a-mole）ため撤回した。対処には辺単位ではなく
面積単位の可視率計算（表自体を面積分の形に持つか、部分可視の合成則を別に持つ）が
要ると見ている。次に着手するならここから。

10迷路×2条件×420秒の試算は、直接積分だと約53時間（教授セッションの独立検算）に対し、
表を使うと約0.4時間（約130倍速）になる見込み。

表の生成: `mouse/build_ir_response_table.py`（版管理下）。生成物
`mouse/data/ir_response_table.npz`（壁・約5.3MB）・`mouse/data/ir_post_table.npz`
（柱・約5.3MB）も版管理下に直接置いた（合計約10.6MBで十分小さい）。

## 追記2（2026-08-21）: 目安を「壁の有無の判定が覆らないこと」に切り替えた

教授セッションの独立検算（乱数種777・200姿勢）で、上の追記1で報告した数値
（満量比誤差 中央値0.39%・最大34.8%）が**標本によって大きく動く**こと
（種を変えると最大78.6%）、および**壁の有無の判定が500姿勢中2〜8件で覆る**ことが
分かった。判定が覆ることは地図の誤りに直結する（`note_033` の第1工程が減らそうと
している当のもの）ため、**満量比の誤差という目安そのものを撤回**し、
**「壁の有無の判定が覆らないこと」を直接の目安にした**。

### 対処: 精度が粗くなる姿勢を検出し、その姿勢だけ直接積分に落とす

`fast_response`（表＋解析的な面の列挙）が誤りやすい姿勢の特徴（隣接・同一平面の
壁・柱の組が支配的な寄与を作っている）を検出し、該当する姿勢だけ `response()`
（直接積分）に切り替える `fast_response_or_direct()` を追加した
（`mouse/ir_sensor.py`）。検出条件（`_has_ambiguous_adjacency`）:

1. `_fast_response_breakdown()` で矩形ごとの寄与を求める
2. 最大寄与の2%以上を「支配的」とみなす
3. 支配的な矩形が、近傍のどれか（相手側の寄与の大小は問わない）に隙間20mm
   （柱1本ぶん）以内で隣接していれば、直接積分に切り替える

相手側の寄与を問わない理由: 実例で、支配的な寄与（柱、寄与0.42）のすぐ隣にある壁の
「その壁自身の独立な寄与」は7.6e-4と小さかったにもかかわらず、直接積分では2つが
強く干渉して合計が1.7e-6まで潰れた（壁の有無の判定が覆る典型例）。相手側の寄与の
大小を条件にすると、この組を取り逃す。

### 速さについて（未解決のまま報告する）

**現在の既定値では、この検出条件がほぼ全ての姿勢で真になり、速さがほとんど出ない**
（実測: 実迷路500姿勢×3乱数種で直接積分1.0倍）。原因は迷路の構造そのものにある:
柱は格子点すべてに立つので（`classic.geometry.wall_obstacles`）、**どの壁も必ず
両端で柱に隣接している**。検出条件を絞る（支配的の基準を上げる・距離で絞る）と
速さは戻る（実測: 距離150mm・支配的10%以上に絞ると約1.2倍、距離60mm・10%以上で
約2.0倍）が、絞るたびに壁の有無の判定が閾値0.05で500件中1〜8件覆る組み合わせが
再発した。**正しさを優先し、既定は「取りこぼしが出ない」側（支配的の基準2%・
距離は実質 `max_range_m` まで）にしてある。**

`fast_response`（フォールバックなし。表引きだけ）そのものは高速のまま
（実測: 約1.15ms、直接積分の約49倍）。フォールバックの検出条件を絞り込む作業は
持ち越しの課題とする。速さが要る用途では `fast_response_or_direct` の
`adjacency_significance_frac`・`adjacency_dominant_max_d_m` を絞ることを検討できるが、
**絞るたびに壁の有無の判定の食い違いが再発しないか、
`tests/test_ir_sensor.py::test_wall_presence_decision_is_stable` で必ず確認すること**。

### 実測（`tests/test_ir_sensor.py::test_wall_presence_decision_is_stable`・実迷路
maze_41001・500姿勢×乱数種3つ・4本のセンサ無作為選択・区画内±40mm・方位無作為）

| 指標 | 実測 |
|---|---|
| 壁の有無の判定の食い違い（閾値0.05〜0.30すべて） | **0/500** |
| 満量比の誤差（中央値・最大） | 0.000%・0.000%（`fast_response_or_direct` は該当姿勢を直接積分するため） |

## 追記3（2026-08-21）: 壁と柱を区別せず同一平面で統合した（決定的な原因の特定）

教授セッションが実測で確認した事実: 壁厚12mm・柱12mm角はどちらも格子線上に中心を
持つので、同じ壁面の上では中心・半長が完全に一致し、連続している場合の隙間は
厳密に**0.000mm**（本物の開口部だけが168mm級）。**これは偶然ではなく規格による。**
以前の「同一平面をまとめる」修正が失敗したのは、**壁だけをまとめて柱を除外して
いたため隙間が残っていた**ため、という指摘どおりだった。

### 対処: 壁・柱を区別せず、隙間 <= 5mm（本物の開口部よりずっと小さい閾値）で連続する
矩形をすべて1枚の合成パネルとして統合した（`mouse/ir_sensor.py::_fast_response_breakdown`）。

統合すると**新たに2つのバグ**が出た（どちらも「合成パネルが表の前提（84mm半長の
1枚パネル）よりずっと長くなる」ことが原因）:

1. **横ずれの基準点の誤り**: 「合成パネルの中心からのずれ」を横ずれとして表を引くと、
   合成パネルが長いほどセンサの足が中心から遠くなり、表の届く範囲を外れて
   ゼロになった（実例: 直接0.82に対し表引きが3e-12）。**「センサの足に最も近い、
   表がカバーできる範囲（半長ぶん）の仮想中心」**を使うよう直した（足が奥深くに
   あれば横ずれ0＝内部の値に収束し、端の近くにあれば端からのずれとして正しく
   評価できる）。
2. **遮蔽判定の標本点が薄まる**: 遮蔽の標本点を合成パネル全体（時に500mm超）に
   一様配置すると、足の近くが完全に見えていても、遠く離れた無関係な区間が
   たまたま遮られているだけで「見えている割合」が薄まり、過小評価が残った。
   標本点を**仮想中心±半長の局所窓**に絞るよう直した。

### 結果

`fast_response`（フォールバックなし・表引きのみ）単体の精度が大きく上がった:
実迷路500姿勢×3乱数種で、満量比誤差 中央値0.629%・最大37.7%（統合前は中央値
0.4%程度は同水準だが最大は70%超だった）。

**しかし、壁の有無の判定を500/500件すべてで正しくするための安全弁
（`fast_response_or_direct`）の発動条件を緩められなかった。** 支配的な矩形までの
距離を300mm（`max_range_m`の350mmとほぼ同じ）まで許すとようやく0/500を達成する
が、そこでは**500姿勢中500件すべてが直接積分に落ちる**（実測）。距離を60〜250mmに
絞ると速さは1.0〜2.0倍まで戻るが、閾値0.05で500件中1〜32件の食い違いが再発する。
統合とバグ修正で `fast_response` 単体の精度は上がったが、**「どの姿勢が安全か」を
安価に見分ける方法がまだ無い**、というのが正直な現状である。

### 実測（`tests/test_ir_sensor.py`・実迷路maze_41001・500姿勢×乱数種3つ）

|---|---|
| 壁の有無の判定の食い違い（閾値0.05〜0.30すべて・`fast_response_or_direct`） | **0/500（維持）** |

## 追記6（2026-08-21）: 実機の実測とモデルが合った（問い C の一部が解けた）

ユーザから**実機の実測データ**が提供された。正面に壁を置き、ロボットの距離を 200mm から
50mm まで 5mm 刻みでずらし、左右の前方センサの AD 変換の値を記録したもの
（一次データ = `mouse/data/ir_measured_front_20260821.csv`・版管理下）。
センサの型番・LED 駆動電流・増幅率は現時点では提供されていない。

再現手順 = `verification/audit_051_measured_vs_model.py`。

### 当てはめ方

実機の利得（AD 値 ÷ モデルの無次元値）は未知なので自由パラメータに取る。距離の基準点
（機体の前端か、センサの取り付け位置か）も未確認なので、距離のずれも自由パラメータに取る。
**形だけを比べる。**

### 結果

| センサ | 当てはめ帯 | 距離のずれ | 利得 | 残差 RMS |
|---|---|---|---|---|
| 右 | 80〜200mm | **+0.5mm** | 4454 AD・単位⁻¹ | **0.77%** |
| 左 | 120〜200mm | −1.5mm | 5386 AD・単位⁻¹ | 1.58% |

右センサは、距離が 2.5 倍動く帯にわたって残差 1% 未満でモデルに乗った。距離のずれが
ほぼゼロで済んだのは、`mouse/params.py` のセンサ取り付け位置が実機に近いことの傍証でもある。

冪則の傾き（log-log の当てはめ、120〜200mm）: 実測 左 −1.94 / 右 −1.90、モデル −1.94。

### 実測の形が仕様値を選んだ

利得を毎回最適化したうえで離隔と半値角を振ると、残差が最小になるのは
**離隔 6.5mm・半値角 5.0°**（残差 0.77%）だった。どちらを動かしても残差は増える
（離隔 6.0mm で 1.62%・7.0mm で 1.75%、半値角 4° で 6.71%・6° で 4.07%）。
ユーザから独立に提供された仕様値を、実測の形が選んだことになる。

### 合わなかったところ

1. **左センサは 110mm より近い側で外れる。**実測がモデルより高く出て（95mm で +15%）、
   その後 3345〜3670 で寝る。飽和だけでは説明がつかない（飽和なら実測は下に外れる）。
   左右で形そのものが違うので、**個体差は利得ひとつの係数では表せない。**
2. **飽和がモデルに入っていない。**実測は 3300〜3670 で寝るが 12bit の満量は 4095 である。
   現行の `adc()` は満量での硬いクランプしか持たない。実機は満量の手前から寝る。

### まだ確かめられていないこと（測定の条件そのものによる限界）

入射角 0°・横ずれ 0 の 1 条件しか測っていないので、確かめられたのは**正対したときの
距離依存の形だけ**である。入射角の依存・横ずれの依存・遮蔽・多重反射・縦配置と横配置の差は、
このデータでは何も言えない。

### 決定的な予測が未検証のまま残っている

モデルの最も効く特徴は**応答が非単調でピークが 44mm にある**ことだが、実測は 50mm で
止まっている。しかもピーク（AD 換算 3693）と 50mm（同 3581）の差は 3% しかないので、
50mm 付近だけでは判別できない。内側へ入ると桁で落ちる:

| 距離 | 離隔 6.0mm | 離隔 6.5mm | 離隔 7.0mm |
|---|---|---|---|
| 40mm | 4339 | 3635 | 3003 |
| 30mm | 3494 | 2554 | 1822 |
| 25mm | 2276 | **1452** | 895 |
| 20mm | 833 | **415** | 197 |
| 15mm | 67 | 20 | 5 |

**25mm と 20mm まで測れば決着する。**ここでモデルが外れれば、離隔か半値角のどちらかが違う
（ピーク位置は離隔 6.0〜7.0mm・半値角 4〜6° の範囲で 34〜59mm まで動く）。

### なぜこれが効くか — 区画中心での距離

区画中心にいるとき、光軸に沿った壁面までの距離は **前方センサ LF が 53.0mm・
側方センサ LS が 70.1mm**（区画 180mm・壁厚 12mm から計算）。

前方センサはピーク 44mm のすぐ外側にいる。**9mm 前進すればピークに乗り、20mm 前進すれば
33mm すなわち山の内側に入って値が下がり始める。**前方の壁判定は、1 区画のうちの前進だけで
単調でなくなる。しきい値ひとつで切る現行の `classic/sensing.py` の構造が成り立たないのは
このためである。

## 追記7（2026-08-21）: 角度の実測から、モデルに欠けていた鏡面成分が見つかった

ユーザから 2 つめの実測データが提供された（`assets/angle_vs_sensor.csv`・版管理下）。
再現手順 = `verification/audit_052_angle_vs_model.py`。

測定の条件（ユーザの説明）:
- **センサ 1 本ずつ別々に測ったもの**（4 本を同時に測ったのではない）
- **光軸が壁に垂直に当たる状態を 0 度**とし、そこから**壁の角度**と距離を変えた
- 距離 150／160／170／180mm × 角度 −25°〜+25°（5° 刻み）× 4 本

したがってモデル側の幾何は「光軸に沿った距離を保ったまま、入射角だけを変える」になる。

### 実測の形（センサごと・距離ごとに角度 0 で規格化して平均）

| 角度 | −25 | −20 | −15 | −10 | −5 | 0 | +5 | +10 | +15 | +20 | +25 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 実測 | 0.71 | 0.74 | 0.77 | 0.83 | 0.98 | 1.00 | 0.85 | 0.77 | 0.74 | 0.72 | 0.70 |
| 現行モデル（鏡面 0） | 0.92 | 0.94 | 0.97 | 0.99 | 1.00 | 1.00 | 1.00 | 0.99 | 0.97 | 0.94 | 0.92 |

**鋭い山が広い台の上に乗っている。**0 度から ±10 度で 0.80 まで急に落ち、そこから
±25 度までは 0.70 までゆっくり落ちるだけである。拡散反射だけのモデルは ±25 度でも
0.92 にしかならず、この形を出せない（残差 RMS 0.183）。

### 鏡面成分を入れると合う

| | 鏡面成分 | とがり | 角度のずれ | 残差 RMS |
|---|---|---|---|---|
| 全体（4 距離 × 4 本の平均） | **0.12** | **50** | +2° | **0.0070** |
| 距離ごと（180/170/160/150mm） | 0.12〜0.15 | 50〜80 | +2° | 0.010〜0.033 |
| センサごと（LF/LS/RS/RF） | 0.10〜0.12 | 25〜50 | +1〜+2° | 0.005〜0.036 |

残差が 26 倍良くなる。4 つの距離と 4 本のセンサが、互いに独立に同じ範囲の値を選んだ。

とがり 50 は `cos^50 φ` の半値幅で 9.5° にあたる。鏡面の反射は壁の傾きの 2 倍だけ振れるので、
壁を 5 度傾ければ反射は 10 度動いて視野から外れる。実測が 0 度と ±5 度の間で急に落ちるのは
これで説明できる。

角度のずれ +1〜+2° は、測定台の据え付けか光軸のアライメント誤差（±1° と聞いている）と
矛盾しない大きさである。

### 一組のパラメータで両方の実測が説明できる

鏡面成分を入れても、追記6 の距離の実測（正対・200〜80mm）は壊れない。

| 反射面の設定 | 距離の実測への残差 RMS |
|---|---|
| 鏡面なし（現行の既定） | 0.73% |
| 鏡面 0.12・とがり 50 | 0.78% |

正対しているときは鏡面成分が常に効くので、利得に吸収されて形が変わらない。
**距離の実測と角度の実測を、拡散 0.8・鏡面 0.12・とがり 50 という一組で同時に説明できる。**

### これは何だったか

`note_034` は最初から「拡散を主とし、**鏡面成分も係数で持てる形（ゼロにしない）**」と
書いていた。ところが `SurfaceSpec` の既定は `specular = 0.0` で、表の生成も検査も
すべて鏡面なしで行っていた。実測は鏡面成分がゼロではないと言っている。

### 壁判定への影響

前方センサが区画中心で見る入射角は 0 度なので、鏡面成分がまるごと乗る。機体が 10 度傾くと
鏡面成分が視野から外れて、値が 2 割ほど下がる。**壁の有無を強度のしきい値で判定するなら、
この 2 割は機体の向きだけで動く。**追記6 で示した「前方センサが山の内側に入る」問題と併せて、
`classic/sensing.py` を作り直すときの前提になる。

### 未解決

- 実測はわずかに左右非対称である（−5° で 0.98、+5° で 0.85）。角度のずれ +2° で大半は
  説明できるが、完全ではない
- 角度は ±25° までしか測っていない。側方センサが迷路で見る入射角はもっと大きくなりうる
- `verification/AUDIT_050_PREREG` の光線追跡との突き合わせは鏡面なしで行う取り決めである。
  実装どうしの照合としては変わらず成立するが、**鏡面成分を入れた版での照合は別途要る**

| 縦配置と横配置の差 | 実機では基板の作り直しが要る |

## 追記8（2026-08-21）: 非単調性の機構を否定対照で確かめ、実測でどこまで言えるかを詰めた

ユーザの指摘（2026-08-21）:「短距離の場合は光のスポットが PT の視野にどんどん入らなく
なる現象は確認できるので、それがシミュレートできているかですね」。

再現手順 = `verification/audit_053_peak_mechanism.py`。

### 機構は再現できている（否定対照）

離隔（LED と PT の間隔）をゼロにすると、**山が消えて距離に対して完全に単調になる**。

| 設定 | 山の位置 | 距離に対して単調減少か |
|---|---|---|
| 離隔 6.5mm（実機の値） | 44mm | いいえ |
| 離隔 0（LED と PT を同じ点に） | 山なし | **はい** |

壊すと変わるので、山は確かに「照射円と視野円がずれて重ならなくなる」ことから出ている。
手計算とも合う: 半値角 5° の照射円の半値半径は `d·tan5° = 0.0875d`。これが離隔の半分と
釣り合うのは `6.5/(2×0.0875) = 37.1mm` で、モデルの山 44mm はその少し外側にあたる。

### 実測でも山の始まりが見えている（ただし決着はしていない）

実測は 50mm で止まっているが、**50〜80mm がすでに `1/d²` よりずっと平らである**。
80mm から 50mm への伸びは、実測 1.51 倍に対し `1/d²` なら 2.56 倍のはずである。

右センサの 50〜200mm 全域を 1 つの利得で当てはめた残差:

| 説明 | 自由パラメータ | 残差 RMS |
|---|---|---|
| 山あり（離隔 6.5mm）・飽和なし | 1（利得） | **2.01%** |
| 山なし（`1/d²`）・飽和なし | 1（利得） | 29.36% |
| 山なし（`1/d²`）＋軟らかい飽和 | 2（天井・利得） | 2.46%（天井 4350） |
| 山あり・離隔も自由・飽和なし | 2（利得・離隔） | 2.01%（**離隔 6.5mm を選ぶ**） |

山ありは**自由パラメータ 1 つ**で説明し、飽和は 2 つ要る。離隔を自由にした走査は
**独立に 6.5mm を選ぶ**（ユーザ提供の仕様値）。山ありの側が有利ではある。

🔴 **ただし残差 2.01% と 2.46% の差は決着と呼べる大きさではない。**飽和の当てはめが選んだ
天井 4350 は 12bit の満量 4095 のすぐ上で、物理としても筋が通る。両方の説明が生き残っている。

### 何が決着させるか

2 つの説明は **44mm より近い側で正反対を予測する**。

| 距離 | 山ありの予測 | 飽和の予測 |
|---|---|---|
| 44mm 付近 | 頭打ち | 頭打ち |
| 30mm | **下がる**（ピークの 0.69） | さらに上がる |
| 20mm | **大きく下がる**（0.11） | ほぼ天井 |

ユーザは「光のスポットが PT の視野に入らなくなる現象は確認できる」と述べている。
**もし実機で読みが実際に下がるところまで見えているなら、飽和だけでは説明がつかず、
山ありで決着する。**「上がらなくなる」までしか見えていないなら、両方が残る。
次にユーザへ確認すべきはこの一点である（新しい測定は要らない）。

## 追記11（2026-08-21）: 他機体の公開記事を調べた — 山の位置は光学系で決まる

| 出典 | 応答の形 | 較正式 |
|---|---|---|
| micromouseonline 2010 | **15mm より近い側で形が変わる**（「近すぎると検出器がスポットを見られない」） | `y = a/(ln x + b)` |
| micromouseonline 2011 | 単調を前提 | `距離 = 100·ln(ADC50)/ln(ADC)` |
| ucgosu.pl 2018 | 20mm まで単調（山なし）。有効範囲 30〜180mm | `ADC = e^(a/(l+b)) + c` |
| usamimi.info 2016 | 近距離で PT が飽和 → LED の電流制限抵抗を上げて解決 | `x = a/ln(y) − b` |

2010 年の記事が述べる機構は本件と同じものだが、**その距離が 15mm** である。山の位置は
おおよそ `離隔 / (2·tan(半値角))` で決まるので、素の赤外 LED（半値角 15〜20°）なら
`6.5/(2·tan15°) ≈ 12mm` となり記事と合う。本機体は SFH4550（3°）＋ ST-1KL3A（6°）の
狭指向角なので、同じ機構でも山が 36〜44mm まで外へ出る。**矛盾ではなく、光学系の違いである。**

### 標準的な較正式は本機体には当てはまらない

ユーザの実測（右センサ）に当てはめた残差:

| 式 | 自由パラメータ | 80〜200mm | 50〜200mm |
|---|---|---|---|
| 2010 記事 `a/(ln x + b)` | 2 | 13.6% | 26.8% |
| 2011 記事 `c·exp(k/x)` | 2 | 8.6% | 21.9% |
| **物理モデル** | **1（利得）** | **0.78%** | **2.01%** |

自由パラメータが半分で残差は 1 桁小さい。標準的な較正式は「単調で指数的に落ちる」形を
仮定しているが、本機体は測定域の内側に山を持つ。**マウサーの定石をそのまま持ち込めない。**

## 追記13（2026-08-21）: 拡散反射率は決められない。単一反射と相互反射の両方を作って差を測る

ユーザの決定（2026-08-21）:
**「拡散反射率を現在実験で求めるのは不可能です。既知の面がないからです。
帯1、帯2 両方行うのが今の正解でしょう。そしてどのくらい結果が違うのか、
例えばテスト迷路の中でセンサ位置や角度を変えて二つのシミュレーションで
測定した結果を見比べてみたい」**

### 背景

`AUDIT_050` の工程2 は「単一反射の仮定は成り立たない」（M2 = 0.03015・帯2）と出たが、
これは壁の拡散反射率 ρ = 0.8 を仮定した値である。ρ を変えると帯が変わる
（`AUDIT_050_RESULT` 追記2・`verification/audit_054_reflectance_sweep.py`）:

| ρ | M2 | 帯 |
|---|---|---|
| 0.5 | 0.0074 | 帯1（相互反射は不要） |
| **0.55 付近** | — | **境目** |
| 0.6 | 0.0128 | 帯2（相互反射が要る） |
| 0.8 | 0.0302 | 帯2 |

既存データでは ρ を縛れない（測定の場面で多重反射が 2〜5% しか占めないため）。
実機で測るには**既知の反射率の面**が要るが、ユーザは持っていない。

### 決めたこと

**ρ を推定して一方に賭けるのではなく、単一反射のモデルと相互反射込みのモデルを
両方実装し、同じ条件で走らせて差を測る。**差が小さければ、どちらを使っても
結論は変わらない（＝ ρ を決める必要がそもそも無かった）ことになる。
差が大きければ、そこが ρ の不確かさが効く場所であり、その場所を特定できる。

これは「知らない量を推定して進む」のではなく、
**「知らないことが結果に効くかどうかを直接測る」**やり方である。

### 次の工程（次セッションの最初の仕事）

1. 面積分に相互反射を足した版を作る（`mouse/ir_sensor.py`。単一反射の版は残す。
   切り替えは引数で行い、既定は現行のまま挙動を変えない）
2. **テスト迷路の中で、センサの位置と角度を振って両方のモデルで測り、結果を見比べる**
   - 区画中心だけでなく、実走で起きる横ずれ（`exp_030` の実測で 17.5〜35.7mm）と
     方位ずれを含む範囲を振ること
   - 見るのは値そのものだけでなく、**壁の有無の判定が覆るかどうか**
     （`note_033` 第 1 工程が減らそうとしている当のもの）
3. 差が出る場所が特定できたら、そこで初めて ρ の扱いを決める

### 事前登録が要る

この比較も `RESEARCH_PLAN` §12-9 の対象である。**主判定量を 1 つの実数に落とし、
実数直線を切れ目なく分割してから測ること。**「壁の有無の判定が覆った件数」を
主判定量に据えるのが素直だが、閾値の決め方（新しいモデルの上での壁判定は未実装）に
依存するので、そこを先に決める必要がある。
