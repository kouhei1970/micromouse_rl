# 試行台帳 — 何を試し、何ができて、できなかったのは何故か

- 新設: 2026-08-20（ユーザ裁定）
- 更新: 試行を 1 つ終えるたびに 1 行追加する。**削除しない**（否定的な結果ほど残す価値がある）

## 🔴 この文書は「作法の登録簿」ではない（消さないこと）

`docs/RESEARCH_PLAN.md` §12-6 は「**新しい教訓は登録しない。テストか自動検査を書く。書けないものは書かない**」と
定めている。あれは**作法（working convention）の登録簿が自己増殖した事故**への対策であり、
**実験の結果と、できなかった理由の記録**はそれとは別物である。

- §12-6 が禁じるもの: 「今後は〜に気をつける」型の、読解で当てる作法の逐次登録
- **本台帳が集めるもの**: 実際に走らせた試行と、その帰結、およびできなかった原因の分類

将来のセッションが本台帳を「旧慣行の再現」と見なして削除してはならない。

## 方針（ユーザ裁定 2026-08-20）

> 強化学習の最終ゴールはセンサ情報のみだが、それに至る過程でいろいろなことを試せばよい。
> そこから得た知見が最終ゴールの参考になるかどうかは**未知**なので、やってみて試して知見をまとめる。
> **「これはやらない・これはやる」を先に考えず、できることはやってみる。**
> できないことは何で、それは何故できないのか — **計算資源のせいか、物理的に不可能か、
> 計算機が速ければできるのか** — をまとめていくのが目的である。

したがって:

1. **事前に「筋が悪い」という理由だけで試行を却下しない。**却下するなら、却下した事実と理由を本台帳に書く
2. **できなかったときは「できなかった」で終わらせず、下の分類まで踏み込む**
3. 否定的な結果は**成果**として扱う（`note_026` の「短期文脈でも隠れ 32 次元の再帰構造でも届かない」は成果）

## できなかった理由の分類（必ずどれかに当てる）

| 記号 | 分類 | 判別のしかた |
|---|---|---|
| **R-計算** | 計算資源が足りない | **計算機が速ければ／並列を増やせば届く**。所要量を見積もって書く（例: 「10 倍の試行が要る」） |
| **R-時間** | 実時間が足りない | 資源はあるが期間内に終わらない。必要な期間を書く |
| **P-物理** | 物理的に不可能 | 物理限界・摩擦・センサ分解能などが禁じている。**限界値と要求値を並べて書く** |
| **M-手法** | 手法として届かない | 資源を増やしても収束しない／構造的に表現できない。**何が足りないのかを書く** |
| **I-実装** | 実装の欠陥 | 直せば通る。直したなら直したコミットを書く |
| **U-未知** | 切り分けられていない | **ここに置いたままにしない。**次に何を測れば切り分くかを書く |

**`U-未知` のまま放置された行は、次のセッションの仕事である。**

## 決着した論点（ユーザ裁定 2026-08-20:「古い裁定は破棄せよ」）

| 論点 | 決着 |
|---|---|
| 過程の実験で**教師信号**（蒸留・模倣・古典軌跡の教師あり学習）を使ってよいか | ✅ **使ってよい。**裁定 08-14 の禁止規定は**破棄**（`RESEARCH_PLAN` §8 を改訂）。<br>最終形の入出力契約（センサのみ → モータ電圧）は変わらない |
| `T_ideal` を**報酬の正規化**に使うことは注入に当たるか | ✅ **可。**上と同じ扱い。試したら本台帳へ記録する |
| **報酬契約の凍結**（「確定後の変更は不可」） | ✅ **破棄。**変更は可。ただし**変更内容と判定条件を結果を見る前に登録**する |
| 「古典の完成まで RL の新実験を起票しない」という門 | ✅ **破棄。**優先順として古典を先に進めるが、**禁止ではない** |
| 「S5 斜めを最後に置く」（`note_030`） | ✅ **破棄**（段階表ごと。`note_031`）。方式の採否は経路ごとに最適化器が決める |

🔴 **破棄されたのは「何を試してよいか」の制限だけである。**検証の作法
（①事前登録 ②錨の独立再計算 ③否定対照）は破棄されていない。
報酬や手法を変えるなら、**変えることと判定条件を結果を見る前に登録する**。
これが無いと「いろいろ試した」と「都合の良い結果を選んだ」が区別できなくなり、試行そのものの価値が消える。

## 破棄しなかった裁定と、その理由

| 残すもの | 理由 |
|---|---|
| **予約 seed 帯 1000〜40999 を学習・調整に使わない** | 一度汚染すると**後から復元できない**。作業の進み方に依存する判断ではなく、評価の健全性そのもの |
| **完成基準の分母は物理限界からの理想タイム**（実機は使わない） | ユーザ裁定 08-20 が**強化した**もの。`note_031` の η はこれの実装 |
| **最終形の入出力契約＝センサのみ → モータ電圧** | 裁定 08-20 で**再確認された** |
| 事前登録・錨の独立再計算・否定対照の 3 点 | 上記のとおり、破棄の対象外 |

これらも破棄すべきなら、ユーザがそう言った時点で本表を書き換えること。**勝手に残し続けない。**
