## 1. いま何がばらばらか

| 置き場 | 形式 | 面数 | 出所 | 年・区分の確からしさ |
|---|---|---|---|---|
| `competition/mazes/contest_historical/` | npz | 102 | NTF ヒストリーアーカイブ（BMP） | **一次資料で確定** |
| `competition/mazes/contest_reference/` | npz | 18 | `kerikun11/micromouse-maze-data` | **ファイル名からの推測**（未確認） |
| `competition/mazes/eval/` ほか | npz | 多数 | 生成 | — |
| （版管理外） | アスキー | 15 | NTF `taikai/map.html` | 一次資料。**102 面と 5 面で食い違う** |

問題は 3 つ。

1. **同じ迷路が別の場所に別の形式で入っている**（1980〜1994 は npz とアスキーの両方）
2. **npz は差分が読めない。**壁が 1 枚変わっても `Binary files differ` としか出ない。
   `note_035` で見つけたような**資料どうしの食い違いを、版管理の上で追えない**
3. **出所・年・区分・確からしさが、ファイル名と manifest に散っている。**
   迷路そのものと一緒に旅をしない

## 2-0. 🔴 「保存庫」と「置き場」は別物である

最初の案は**アーカイブ**（もう作り直せないものを保存する場所）として書いていた。
ユーザの是正により、**データベースの置き場**として設計し直す。何が変わるか:

| | 保存庫として作ると | 置き場（データベース）として作ると |
|---|---|---|
| 目的 | 失わないこと | **引けること** |
| 置き場所 | `competition/` の下（評価ハーネスの持ち物） | 🔴 **リポジトリ直下 `mazes/`。誰の持ち物でもない共有の資源** |
| 中身 | 実在した競技迷路だけ | **迷路と名の付くもの全部**（種別で分ける） |
| 使い方 | 必要なとき取り出す | **属性で絞って一括で回す**のが常用 |
| 同じ迷路が 2 つ | 別々に置いておく | **中身の指紋で自動的に気づく** |

置き場所を `competition/` から出す理由: 迷路は**評価だけのものではない**。
学習・解析・歴史の照合が同じものを見る。評価ハーネスの下に置くと、
「凍結された評価用の資産」という色が付いてしまう。

## 2. 提案 — 1 迷路 1 テキストファイル（前書き ＋ アスキー図）

**アスキーを正本の保存形式にする。npz は要るときに生成する。**

### 2-1. なぜアスキーを正本にするか

- **差分が読める。**壁 1 枚の違いが `git diff` にそのまま出る。
  資料どうしの食い違いを版管理で追える
- **道具が要らない。**`cat` で中身が分かる。人が目で検算できる
- **壊れない。**numpy の版に依存しない。30 年後も読める
- npz は**生成物**にすればよい。読み込み器を 1 つ用意して、
  既存のコードにはこれまでと同じ配列を渡す

### 2-2. 🔴 ただし、アスキーの書き方は選ばないといけない

`note_035` で**実際に踏んだ落とし穴**がある。NTF の `map.html` が使っている
`|` と `_` の詰めた書き方は、**横壁が下線 2 文字ぶんで描かれ、柱の位置にも `_` が出る**。
この規則を取り違えて、最初の実装は 15 面すべてで往復検証に落ちた。

**詰めた書き方は正本にしない。**次の書き方を採る。

```
+---+---+---+
|           |
+   +---+   +
|   |   |   |
+---+---+---+
```

- 柱は `+`、横壁は `---`、縦壁は `|`、開通は空白
- **どの文字がどの壁かが一意に決まる。**解釈の余地が無い
- 区画の内側が 3 文字あるので、**`S`（始点）・`G`（終点）を書ける**
- 未知の壁を `?` で表せる（`WallState` の 0＝未知に対応）
- 16×16 なら 65 文字 × 33 行

**幅は食うが、正本は読めることが第一である。**詰めた書き方は表示用の別関数にすればよい。

### 2-3. ファイルの形

```
---
id: AllJapan_015_1994_exp_fin
size: [16, 16]
start: [0, 0]
start_heading: N
goal: [[7, 7], [8, 7], [7, 8], [8, 8]]
series: AllJapan
edition: 15
year: 1994
class: expert          # expert | freshman | (なし)
stage: final           # final | preliminary | (なし)
source: "NTF ヒストリーアーカイブ MazeImage/AllJapan_015_1994_classic_exp_fin_16x16.bmp"
source_url: "https://www.ntf.or.jp/mouse/history/index.html"
retrieved: 2026-08-23
confidence: disputed   # confirmed | single-source | disputed
disputes: [AllJapan_015_1994_exp_fin__map_html]
notes: "taikai/map.html のアスキー版と縦2枚・横3枚の壁が食い違う。どちらが正しいかは未確定"
---
+---+---+---+ ...
```

**前書きに置く理由**: 出所・年・区分・確からしさが**迷路と一緒に旅をする**。
manifest が迷路本体とずれる事故が起きない。

### 2-4. 食い違う迷路は、両方とも残す

`note_035` で見つけた 5 面のように、資料が食い違うことがある。
**どちらかを捨てない。**別の `id` で両方を収載し、`disputes:` で相互に指させる。

- 解析の側が「確定しているものだけ使う」を選べる（`confidence: confirmed` で絞る）
- 後日どちらが正しいか分かったときに、履歴として何が起きたか読める

### 2-5. 置き場と名前

```
mazes/                              ← リポジトリ直下。共有の資源
  README.md                         ← 何がどれだけ入っているか・引き方
  INDEX.tsv                         ← 生成物。属性 ＋ 指標を 1 行 1 面
  contest/                          ← 実在した競技迷路
    AllJapan_015_1994_exp_fin.maze
    AllJapan_015_1994_exp_fin__map_html.maze   # 食い違う別資料の版
    EastJapan_013_1995.maze
    World85_fin.maze
  reserved/                         ← 確保済みで変更禁止の生成迷路（評価用 20 迷路など）
    eval_1018.maze
```

- **種別で 1 段だけ分ける**（`contest` / `reserved`）。それ以上は掘らない。
  年・地区・区分は**前書きで引く**もので、階層で表すものではない
- 名前は人が読むためのもの。**引くのは `id` と前書きの属性で行う**
- `INDEX.tsv` は**生成物**。本体とずれていないことを検査で担保する

### 2-5b. 🔴 中身の指紋を持たせる

前書きに **`content_sha256`**（壁の並びだけから決まる指紋）を入れる。

- **同じ迷路が別の出所から入ってきたら、自動的に気づく**
- 逆に、**同じ迷路のはずなのに指紋が違えば、資料が食い違っている**
  （`note_035` で見つけた 5 面がまさにこれ）
- 前書きの他の項目（年・出所・確度）は指紋に含めない。**壁だけで決める**

これがあると、`INDEX.tsv` を作る段で重複と食い違いが機械的に洗い出せる。

### 2-5c. 引き方（これが「置き場」の本体）

`common/maze_db.py` に置く。

```python
from common.maze_db import MazeDB

db = MazeDB()                                   # mazes/ を読む
db.get("AllJapan_015_1994_exp_fin")             # 1 面
db.query(kind="contest", stage="final",         # 属性で絞る
         confidence="confirmed")                #   → 決勝で確度の高いものだけ
db.query(year=range(1980, 1995), series="AllJapan")
db.walls(rec)                                   # v_walls / h_walls を返す（既存コードへ）
```

**属性で絞って一括で回せることが、この置き場を作る理由である。**
`note_035` で「決勝・予選・フレッシュマンを混ぜて比べてはいけない」と分かったが、
いまは手で選り分けている。`db.query(stage="final")` で済むようにする。

### 2-6. 検査

🔴 **検査は 3 段で置く**（`tests/test_maze_db.py`）。

1. **往復**: すべての面で `dumps(load(f))` が元のファイルと**1 文字単位で一致**
   （`note_035` の落とし穴を二度踏まないため）
2. **構造**: 外周が完全・ゴール 2×2 の内側に壁が無い・スタートから到達できる・
   **スタート区画の開口が 1 つだけ**（`docs/COORDINATE_SYSTEM.md` §1 の発進方向が一意になる条件）
3. **索引の同期**: `INDEX.tsv` を生成し直して、版管理下のものと一致する

### 2-7. 座標系

`docs/COORDINATE_SYSTEM.md` に従う。**アスキー図は上が北**（§2 の言い換え）。
読み込み器が図の上下と `y` の向きを変換する。**この変換は 1 箇所にだけ書く。**

## 4. 生成迷路をどこまで入れるか

「置き場」として設計し直したことで、**線の引き方がはっきりした。**

| 種類 | 入れるか | 理由 |
|---|---|---|
| 実在した競技迷路 | **入れる**（`contest/`） | 作り直せない。これが中核 |
| **確保済みの評価用迷路**（20 迷路） | **入れる**（`reserved/`） | 作り直せるが**作り直してはいけない**。ここでは**ファイルが正本**であり、生成器は由来にすぎない |
| 学習中に作る迷路 | **入れない** | その場限り。seed と生成器が正本。置き場に置くと嘘になる |

判定の規準はひとつ。**「この迷路の正本はファイルか、生成器か」。**
ファイルが正本のものだけを置き場に入れる。

### 8-3. 🔴 権利の状況で扱いが分かれる

| 出所 | 公開リポジトリへの取り込み |
|---|---|

### 8-4. 教授セッションの提案

1. **まず kerikun11（MIT）から入れる。**権利が明確で、書き方が柱 `+` 方式で本設計と同系統。
   **未知壁 `.` の実例がある**ので §6-1 の未解決点にそのまま答えが出る
2. **mazefiles は「何が存在するかの索引」として使い、データは持ち込まない。**
   面数は魅力だが、許諾が無いうえ一次資料でもない（編者自身が又聞きだと明記している）。
   埋めたい年が分かったら、**一次資料（NTF・各国協会）へ当たり直す**
3. NTF の 1995〜2003 の画像は、既存の BMP 読み取り機を転用できるか試す価値がある
