# 事前メモ 001: 壁の「検出」は現行のどこにも無い（P6 第 3 部の前提）

- 作成: 2026-08-14 午前 准教授セッション（独立検証担当）
- 位置づけ: **P6 の改訂中に届ける事実の報告**（レビューではない）。手戻りを防ぐため先に出す
- 発端: 教授の追伝「確率的マッピング/SLAM が P6 第 3 部として加わる」＋
  「凍結評価ハーネスとの整合をどう保つか」の確認依頼

## 1. 教授の追加観点への回答 — **境界は綺麗。ハーネスは無変更でよい**

**評価器が方策から受け取るのは 2 つだけ**である（`competition/policy_interface.py`）:

- `act(obs) -> (vl, vr)` — **14 次元の観測 → 左右モータ電圧**
- ライフサイクルの callback（`on_maze_start` / `on_run_start` / `on_run_end` / `on_retrieval`）

**評価器は方策の壁の信念を一切読まない。**判定は**物理的な事象のみ**
（goal / collision / tipover / stuck / timeout・計時は前端のセンサ通過）。
**E1 の最短性の確定判定も方策側（`competition/explore_e1.py`）にある。**

> **したがって、方策の内部を確率的マッピングに変えても、
> 凍結評価ハーネスは変更不要である。境界は保たれる。** ✓

## 2.【🔴 事実】古典トラックには「壁を検出する」処理が**存在しない**

**`competition/baseline_classical.py` の設計記述（L23-24）**:

> **セル中心に到達し停止するたび（SENSE）、`bind_maze` で受け取った真の壁配列から
> 現在セルの 4 方向を読み取り、既知地図に書き込む。**

**`competition/baseline_slalom.py` の `_do_sense`（L976-977）**:

> **現在セル (cx,cy) の 4 方向の真の壁を読み、既知地図に書き込む。L0-a/L0-b と同一。**

**すなわち全ベースラインが `requires_privileged = True` で真の壁配列を受け取り、
距離センサを壁の判定に使っていない。壁の読み取りは構成上 100% 正確である。**

> **🔴 したがって、ユーザの推奨（「離散的な壁確認は失敗確率が高い。複数サンプリングで
> 確認していた。SLAM 理論等を取り入れるとよい」）が対処する失敗様式は、
> 現行のシミュレーションに存在しない。**
> **実機の問題であって、いまのモデルの問題ではない。**

## 3. P6 第 3 部を設計する前に決めるべきこと

| 選択 | 内容 | 代償 |
|---|---|---|
| **(a)** | **シミュレーション側を変え、壁の判定を距離センサ由来にする**（雑音つき） | **新しい失敗様式を導入する変更**であり、**古典ベースラインの成績が下がる** → **参照線が動く**（M4/M5 の基準値に波及。`AUDIT_008` の系譜） |
| **(b)** | **対象を RL 側にする** | RL 方策は **14 次元の観測のみ**で壁地図を持たない。**そもそも確率的も決定的も無い** — 「マッピングを持たせる」こと自体が新しい設計（レバー ②「記憶」と同じ領域） |
| (c) | 第 3 部を**実機移行時の課題**として登録し、いまは着手しない | 実機を持たない現状では検証できない |

**⚠️ (a) を選ぶなら、それは「古典ベースラインを弱くする変更」である。**
**古典トラックの目的は「学習が超えるべき最良の参照線」なので、
弱くする変更を入れるなら、その理由（実機との整合）を明示的に裁定に載せる必要がある。**

## 4. 斜め走行との接続（P6 第 1・2 部にも効く）

**現行の読み取りの契機は「セル中心」である**（L0-a/b は停止時、L0-c は通過時）。
**斜め走行はセル中心を通らない経路**なので、**読み取りの契機そのものを再定義しなければならない。**

- L0-c は「停止しないので**通過**で検出する」形に既に拡張されている（`baseline_slalom.py` L59）
- **斜めでは「どのセルを通過したか」の定義自体が変わる**（区画の対角線上を走る）
- **これは第 3 部を入れるかどうかに関わらず、斜め走行の実装が必ず踏む問題**である

**→ P6 の第 1・2 部でも「斜め走行中に壁地図をどう更新するか」を書く必要がある。**
（ユーザの回答②「斜め走行中のセンサ認識・マッピングは実機で成立していた」は、
**実機ではセンサで検出していた**という前提の話であり、**§2 のとおり現行モデルとは前提が違う。**）
