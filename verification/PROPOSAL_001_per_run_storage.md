## 1. 提案する保存形式

### 1-1. 原則

1. **既存の `metrics.json` の構造（`per_course[].trials[]`）を正本とし、列を足す。**
   新形式を作らない。exp_001〜005 の過去データがそのまま読める
2. **集計スクリプトは、評価を都度実行して捨ててはならない。**
   評価器に `metrics.json` を書かせ、集計はその**ファイルを読んで**行う
3. **走行ごとの指標は全件、行動列は代表走行のみ**（正本 §9-3 の原則どおり）

### 1-2. パス規約

```
outputs/<実験名>/latest/metrics.json                 … 最新（既存の慣例どおり）
outputs/<実験名>/archive/<YYYYMMDD_HHMMSS>/metrics.json
outputs/<実験名>/archive/<YYYYMMDD_HHMMSS>/traces/   … 行動列（代表走行のみ）
```

`<実験名>` は**条件ごとに 1 つ**（例: `exp_006d_hp_k8.7e-3_seed1`）。
**条件を 1 つのファイルに混ぜない** — 混ぜると「どの条件の走行か」を後から復元する情報が要る。

### 1-3. トップレベル（既存＋追加）

既存の 19 キーはそのまま。**追加を提案するもの**:

| キー | 型 | 理由 |
|---|---|---|
| `git_rev` | str | **評価時点のコミット。**「再実行すれば確かめられる」を検算可能にするには、当時のコードが特定できる必要がある |
| `model_path` / `model_sha256` | str | どのモデルを評価したか。チェックポイント選択が絡む実験で必須 |
| `band` | str | `gate` / `validation` の別。**現状 `course_dir` から推測するしかない** |
| `eval_seed_rule` | str | 試行 seed の導出規則（再現に要る） |
| `code_config` | dict | 観測次元・報酬オプション・α・k など、方策の学習条件ではなく**評価条件**を決める値 |

### 1-4. 走行ごと（`per_course[].trials[]`）

**既存の 12 フィールドは変更しない**（`outcome` / `complete` / `no_contact_complete` /
`n_steps` / `sim_time` / `n_cells` / `progress_m` / `mean_speed` / `sec_per_cell` /
`action_diff_rms` / `sign_flip_rate_left` / `sign_flip_rate_right`）。

**追加を提案するもの** — いずれも**現在は条件ごとにしか残っておらず、走行ごとに戻せない**量:

| キー | 単位 | 由来 |
|---|---|---|
| `trial_index` | — | 何試行目か。**現在は配列の位置に暗黙**で、抜けがあると復元できない |
| `hf_energy_ratio` | — | 高周波エネルギー比（α は `code_config` に記録） |
| `i_rms` / `i_dc` / `i_ac` | A | モータ電流（左右平均。左右別なら `_l` / `_r`） |
| `p_loss_w` | W | 銅損 I²R |
| `min_wall_clearance_m` | m | 機体外形と壁の最小距離 |
| `lat_max_m` / `lat_rms_m` | m | 横偏差（参考量として残すなら） |
| `n_turns` | — | **旋回回数**（提案。§2 参照） |

### 1-5. 行動列（代表走行）— 「代表」の定義

**選び方を決定的に定める**（実行のたびに変わると比較できない）。条件ごとに **3 本**:

| # | 選ぶ走行 | 理由 |
|---|---|---|
| 1 | 完走走行のうち **`sign_flip_rate` が中央値**のもの（同値なら `course_seed` 昇順で先） | 典型 |
| 2 | 完走走行のうち **`sign_flip_rate` が最大**のもの | 最悪。**指標が壊れるのは最悪側** |
| 3 | **失敗走行のうち最初のもの**（`course_seed`, `trial_index` の昇順。無ければ省略） | 失敗様式の検証に要る |

形式は `traces/<course_seed>_<trial_index>.npz`（`t`, `action_l`, `action_r`,
`wheel_omega_l`, `wheel_omega_r`, `x`, `y`, `yaw` の 1 次元配列）。
**電流の再計算には `action` と `wheel_omega` の両方が要る**（$I=(V-K_eN\omega)/R$）。

サイズ見積り: 1 走行 ≒ 250 ステップ × 8 列 × 8 byte ≒ **16 KB**。3 本で 50 KB/条件。**無視できる。**

## 2. 追加の提案 — `n_turns` を走行ごとに記録する

**理由**: 本日の (c2) 監査で、**実走行の旋回回数が残っていないため、迷路から
最短経路の旋回回数を計算して代用する**必要がありました。旋回は L0-a の時間の
**半分近くを占める**主要因（回帰で 0.85 s/旋回、1 歩 0.71 s）なのに、走行ごとに残っていません。

`n_turns` があれば、時間モデルの係数を**代用なしで**回帰でき、
「距離最適 ≠ 時間最適」の検証が推定を経ずに閉じます。**実装は進行方向の変化を数えるだけです。**
