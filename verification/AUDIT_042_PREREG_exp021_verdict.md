## 2. 検算の層（**L1〜L6。どこまでが独立でどこからが再集計かを分ける**）

| 層 | 何を確かめるか | 独立性 |
|---|---|---|
| **L1** | **出所**: 投入版・モデルの実歩数・生データの所在と SHA-256 | 照合 |
| **L2** | **式**: 各判定量を、保存されている入力から自分で計算し直す | **独立**（式は自分で書く） |
| **L3** | **集約**: 迷路 20 本の中央値 → 6 seed 中央値。**プール集計をしていないこと**も見る | **独立** |
| **L4** | **判定**: 閾値との比較・不等号の向き・境界の扱い | **独立** |
| **L5** | **軌跡層**: 毎歩の `dist_to_goal` / `respawned` から **`min_d` と Q4 の窓を自分で再構成する** | **独立**（**生データが残っていれば**。§4 参照） |
| **L6** | **判定の規律**: 条文が投入後に動いていないか・事前登録していない量が判定に混ざっていないか | 照合 |

**L5 が本監査の核心である。**L2〜L4 は「相手の集計が正しいか」で、
**L5 だけが「判定量そのものが正しいか」を見る**（`AUDIT_039` 第 2 層と同じ位置づけ）。

## 3. 事前に固定する判定の規則

### 3-1. 一致の許容差

| 対象 | 許容差 |
|---|---|
| 判定量の式の再現 | **1e-9**（浮動小数点の表示誤差のみ許す） |
| 集約値の再現 | **1e-9** |
| 軌跡から再構成した `min_d`・`min_d_after_last_respawn` | **完全一致のみ**（整数の区画距離である） |
| 合否の判定 | **完全一致のみ**（数値が合っていても合否が違えば不一致とする） |

### 3-2. 食い違ったときの振る舞い（**作法 35 の事前適用**）

1. **全数不一致（20/20 や 6/6 が全部違う）なら、まず自分を疑う。**
   「見ているものが違う」（抽出先・数えている対象・母集団・版）を最初に確かめる
2. **一部不一致なら、不一致の個体を名指しして、その 1 件を生データまで降りて追う**
3. **自分側の誤りだと分かったら、その旨を自己申告として報告に書く**（隠さない）
4. **相手側の誤りだと確定したら、判定が変わるか変わらないかを分けて書く**

### 3-3. 「未確認」と書く条件

- **生データが無くて確かめられなかった項目は「未確認」と明記する。**
  「見つからなかった」を「無い」と書かない
- **L5 が実行できなかった場合、L2〜L4 の一致をもって
  「判定量が正しい」と書いてはならない**（`AUDIT_039` §4-4 と同じ限定）
