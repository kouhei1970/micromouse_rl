## 1. 定義（**操作的に書く**。裁定 R44 の指示・§9-17）

機体を**機体座標系**で見る（**前方 = $+x$**、**左 = $+y$**、原点 = `privileged_pose()` の基準点）。
方向 $\varphi$ の**支持関数**を

$$h(\varphi)\;=\;\max_{p\,\in\,\text{機体}}\; p\cdot(\cos\varphi,\ \sin\varphi)$$

と定義する（＝ **その向きへの張り出しの最大値**）。

**主用途の列**「**進行方向 $\theta$ で走るときの横方向半幅**」は、
**進行方向に直交する向きへの張り出し**なので $h(\theta+90°)$ である。
**取り違えを消すため、表には $h(\theta)$ と $h(\theta+90°)$ を併記する。**

> **設計側（学生A）が読むのは「横方向半幅」の列である。**
> $h(\theta)$ の列は幾何的定義そのものであり、検算用に置く。

## 3. 対称性 — **厳密に成立**（表が 0〜90° で足りる根拠）

$$h(-\varphi)=h(\varphi),\qquad h(180°-\varphi)=h(\varphi)$$

**61 方位で検定し、最大の破れは 2.78e-17 m**（浮動小数点の丸め）。
**左右対称かつ前後対称**なので、**0〜90° の表から全方位が復元できる。**

## 5. 設計側に効る所見（**判断ではなく材料**）

1. **遷移区間 $\theta\in[0°,45°]$ で、横方向半幅は 0.0400 → 0.0566 m へ単調に増える（+41%）。**
   **斜めへ向き始めた瞬間から余裕が食われ始める**（45° に達してから増えるのではない）
2. **横方向半幅の最大は 45° ではなく $\theta$ = 60° の 0.058301 m**（+46%）。
   **遷移で 45° を行き過ぎると、さらに 0.0017 m 食う**
3. **$h(\varphi)$ の最大は $\varphi$ = 30°（0.058301 m）にあり、45° は極大ではない。**
   凸包の最も張り出した角が **30° 方向**にある（$0.04\sqrt2$ = 0.056569 の 45° より外側）
4. **支配している geom**: $\varphi$ = 0〜45° は `mein_body1`／`mein_body2`（同値で並ぶ）、
   $\varphi$ = 60〜75° は `mein_body2`、$\varphi$ = 90° は `mein_body4`。
   **裁定 R26 で「真の最外側はコーナー片（`mein_body2`〜`5`）」と確定したのと整合する**

## 5-bis.【是正 2026-08-14】**5° 刻みは粗すぎた** — 0.25° 刻みの表を追加した

**学生A から、本表の使用者としての指摘を受けた**（教授経由の版通知）:
**5° 刻みの表を保守側（切り上げ）に丸めて読むと、$\psi\approx8$〜12° で
丸めの損が精密化の得を打ち消し、矩形上界より余裕が小さく出る**（−7.69 対 −6.78 mm）。

**私の側で検証したところ、指摘は正しく、しかも損はより大きかった。**

| 刻み | 切り上げが**矩形上界を超える**最大量 |
|---|---|
| **5°（当初の表）** | **+3.116 mm** |
| 1° | +0.474 mm |
| 0.5° | +0.130 mm |
| **0.25°（追加した表）** | **+0.000 mm** |

**最も損をするのは $\psi\to0^+$ 付近**（切り上げ先が $h(5°)$ になるため）で、
学生A が挙げた 8〜12° より**さらに悪い**。

> **原因**: **支持関数 $h$ は凹でない**（凸体の支持関数は $h''+h\ge0$ を満たすだけ）ので、
> **格子点間を線形に読むのは保守側にならず、保守側に読むには区間の最大を取るしかない。**
> **その最大が、粗い刻みでは矩形上界を上回ってしまった。**
> **精密な値を粗い刻みで配ると、精密さが丸めで消えるどころか害になる。**

**是正**: **0.25° 刻み（361 点）の表を `verification/out/support_function_fine.json` に追加した**
（COMMIT_001 との検算を再度通してから出力している）。**この刻みなら切り上げの損は 0 になる。**
**§4 の 5° 刻みの表は読み物として残すが、計算に使うのは JSON の方**とすること。

> **教訓（作法 21 として登録）**: **数値表を配るときは、使用者がどう丸めるかまで設計する。**
> **「精密な値を粗い刻みで配る」は、精密さを届けない。**
> **本件は使用者（学生A）が使って初めて分かった** — **成果物は、使われるまで検証が終わらない。**

## 6. 未確認・限界

   **床のスロープ・段差がある場合は別に要る**

   遷移区間では機体が回りながら進むので、**掃引の最大は per-$\theta$ の半幅の最大とは一致しない**。
   **これは設計側の仕事**（教授の役割分担どおり）。**私は per-$\theta$ の表と、設計が出てからの検算まで**
3. **車輪・センサポッドを含む全 20 geom で測っている**（除外していない）。
   **🔴 教授裁定（2026-08-14）: 除外なし・全 20 geom で確定。**
   理由: 物理モデル上、**車輪・センサポッドを含むどの geom も壁と接触すれば接触力が生じ走行を乱す**。
   「センサポッドは触れてもよい」という運用は**本プログラムにも競技規約にも存在しない**。
   **裁定 R25 の系譜（物理衝突は実 geom 表面で決まる）どおり全部位で確定する。**
   → **本項は「未確認」ではなくなった**（確定事項として記録する）
4. **モデルは `assets/mouse_v2.xml` 由来の凍結メッシュ**である。
   **機体形状が変われば本表は無効になる**（`MODEL_VERIFICATION_PLAN` の改訂と連動させること）
5. **原点は `privileged_pose()` の基準点**である。$\pm x$ が 0.050 で等しく $\pm y$ が 0.040 で
