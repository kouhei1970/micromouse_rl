# 監査 059（事前登録）: センサモデルの高速化 — 合格条件

- 起票: 教授セッション（2026-08-22）。ユーザの決定（`note_034` 追記16）3「高速にセンサ
  モデルを計算するアルゴリズムを考えて実装する」の実施
- **本書は 1 件も測定していない時点で書いている**

---

## 0. 前提（ユーザの決定・`note_034` 追記16）

- **ρ = 0.8 に確定**（`SurfaceSpec` の既定のまま）。**床の反射は無視する**（`include_floor=False`）
- **壁の有無の判定は合否の基準に使わない。**基準は**信号そのものの誤差**に置く
- 鏡面成分は既定のまま（0.10・とがり 40）

## 1. 何を作るか

`mouse/ir_sensor.py` に **`response_fast()`** を新設する。`response()` は変更しない。

| 段 | 中身 |
|---|---|
| **A** | **直接光**（反射 1 回）。光錐で面を絞り込み、光が当たる範囲だけを積分する |
| **B** | **隅の相互反射**（直角に交わる 2 面の 2〜4 回反射）。床を通る経路は無い |

**段 A を通してから段 B に進む。**段ごとに下の判定を行う。

## 2. 標本（結果を見る前に固定）

- 迷路 `competition/mazes/design_turn_v1/maze_41001.npz`（確保済みの評価用 1000〜40999 の外）
- **無作為 400 姿勢**（区画を無作為に選び中心から ±40mm・方位は一様・センサは 4 本から無作為
  1 本。乱数種 **20260822**）
- **加えて、行き止まりの奥 364 点**（`outputs/audit_056/front_grid.json`。段 B が効く場面を
  必ず標本に含めるため。**段 A でも同じ標本で測る**）

## 3. 錨（結果を見る前に測る）

`σ_ref` = 基準そのものの揺れ ＝ `response(n_grid=48)` と `response(n_grid=64)` の差の
95 パーセンタイル（満量比・上記 400 姿勢）。**基準がこれより細かい差を語れないことを先に測る。**

## 4. 主判定量と分割

- **`M6`** = `|response_fast − response(n_grid=48)|` の **95 パーセンタイル**（満量比）
- **`T`** = `response_fast` 1 回あたりの時間（400 姿勢の平均）

| `M6` | 結論 |
|---|---|
| `≤ 0.01` | **合格。**センサの個体差（数%）より小さく、実機と照合しても区別がつかない |
| `0.01 < ... ≤ 0.03` | 惜しい。差の大きい姿勢を特定して原因を書き、直してから再測定する |
| `> 0.03` | 不合格。設計に戻る |

| `T` | 結論 |
|---|---|
| `≤ 2 ms` | 合格 |
| `2 < ... ≤ 5 ms` | 使えるが目標未達。何が支配的かを測って報告する |
| `> 5 ms` | 不合格 |

**`M6` と `T` は両方満たして合格。**片方だけでは合格としない。

段 B では基準を **`response(n_grid=48)` ＋ 光線追跡の増分**（`max_bounces` 4 と 1 の差・
同一乱数種 777001・15,000 本・`floor_diffuse=0.0`）とし、同じ分割表を当てる。

## 5. 否定対照（検査が作動することの実測。**結果を見る前に走らせる**）

1. **絞り込みを壊す**: 光錐の判定角を半分（LED ±1.5°・PT ±3°）にした版で `M6` を測り、
   **`M6 > 0.03`（不合格の帯）に入ることを確かめる**。入らなければ標本が緩い
2. **格子を壊す**: `n_grid` を 6 に落とした版で `M6 > 0.03` に入ることを確かめる

空振りの側は本体（正しい設定なら帯1）が担う。

## 6. 禁止事項

- **`response()` の既存の挙動を変えない**（既存のテストが通り続けること）
- 確保済みの評価用迷路（seed 1000〜40999）は使わない
- **結果を見てから分割点・標本・乱数種を変えない**
- 壁の有無の判定を合否の基準にしない（ユーザの決定）

2. `verification/audit_059_fast_sensor.py`（§3〜§5 の測定）

## 追記1（2026-08-22）: 否定対照1 が作動しなかったので取り替えた。**判定量と分割表は変えない**

### 何が起きたか

§5 の否定対照1（光錐の判定角を半分にする）は **`M6` = 0.0071 のままで、まったく動かなかった**。
教授セッションが余裕角を段階的に詰めて測り直した実測（基準 = `response(n_grid=48)`・764 姿勢）:

| LED 余裕 | PT 余裕 | `M6` |
|---|---|---|
| 15° / 25°（既定） | | 0.00710 |
| **7.5° / 12.5°（登録した対照）** | | **0.00710** |
| 5° / 8° | | 0.00710 |
| 3° / 6° | | 0.00748 |
| 2° / 4° | | 0.01297 |
| 1° / 2° | | 0.02179 |

### なぜ効かなかったか（対照の設計の誤り）

実装の絞り込みは、**光軸が面と交わる点（矩形内へクランプしたもの）を候補に必ず含む。**
そのため**光軸が当たる面は余裕角がいくら小さくても必ず残る。**寄与の大半はその面なので、
余裕角をいじっても `M6` が動かない。**余裕角は絞り込みを支配していない量だった。**
「壊したつもりが壊れていなかった」ので、この対照では検査の感度を確かめられない。

### 取り替えた対照（実測で作動した）

**光軸が最初に当たる 1 枚だけを積分対象にする**（＝絞り込みを本当に壊す）。

| 対照 | `M6` | 判定 |
|---|---|---|
| 既定の `response_fast` | 0.00710 | 合格 |
| **光軸が当たる 1 枚だけ** | **0.03327** | **不合格の帯（> 0.03）に入った ＝ 作動** |
| `n_grid = 6`（登録した対照2） | 0.51182 | 作動 |

**標本は面の取りこぼしを検出できる。**§4 の判定量 `M6`・`T` の定義と分割表は変えない。

**教訓（作法にせず記録する）**: 否定対照は「パラメータを悪くする」ではなく
**「その量が本当に結果を支配しているか」を先に確かめてから選ぶ**こと。
支配していない量をいじっても対照にならない。
