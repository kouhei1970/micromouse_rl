## 🔴 効いているユーザの決定
1. 単独運用（08-18）／古典はゼロから再構築（08-19）／判定は物理限界からの肉薄度／
   **完成基準の分母に実機は使えない**／**予約 seed 1000〜40999 は使わない**
   （古典の設計帯 41000〜61000、学習用 61001 以降）
2. **探索を信頼できるものにしてから最短走行へ**（08-21・`note_033`）。
   **間違いと分かっている地図で最短走行を走らせない**
3. **光線追跡を前向き計算に採用しない**（測定の道具としては使う）
4. **ρ=0.8 に確定・床は無視**（08-22）／**壁の有無の判定はセンサモデルの妥当性の基準に使わない**
5. **座標系は工学系に統一**（08-23。方位も E=0 から反時計回り）
6. **迷路は「データベース置き場」として持つ**（08-23。`note_036`）
7. **確率ロボティクス的な自己位置推定と、それに従う地図作成を組み合わせる**（08-23）。
   推定器は拡張カルマンフィルタから入れて多仮説へ上げる。センサ劣化は当面入れない
8. **マイコンに実装できるかを常に考慮する**（08-23）。段階ごとに演算量と RAM を実験カードに書く。
   粒子ごとに地図を丸ごと持つ方式は 108 KB で枠を超えるので採らない
9. **斜め探索は必ず達成する**（08-23）。区画中心・軸並行を前提にした層を作らない
10. **経路のノードは柱間の中点。走行ラインは折れ線を滑らかにつないで作る**（08-23）

## 注意点
- p 値は条件比較に使えない／**閾値は「対照で空振り分布を測ってから」置く**／コミットは
  `git commit <パス...> -F -`（`git add -A` 禁止。新規は `git add <パス>` を先に）
- 🔴 **一致確認は、変えたものが効く場面を通っていなければ意味がない**（08-23 の実例:
  「実大会 3 迷路で sha256 一致」は北向き発進しか通しておらず、南向き・西向きの
  角度の分枝の回帰 2 件をすり抜けた）
- 検収の前に `git status` で、subagent と同じファイルを触っていないか確かめる／
  **Artifact は publish するまで直っていない**（画面を見ずに CSS を直そうとしない）
- **隣接値で結果が反転する。単一の標本で判断しない**（`note_031`）／
  **subagent は「通知を待ちます」でターンを終えると落ちる**／**「〜のはず」で検査を設計しない**
- **同じ向きでも角度の分枝（±π・±2π）が違うと走行が変わる**（`COORDINATE_SYSTEM` §10-3b）
