## 1. 状況の要約

M1 は exp_005 で達成済み（gate 0.93 / 1 区画 0.171 s ＝ L0-a の 7.3 倍速）。
**唯一かつ最大の障害は行動振動**（符号反転 75.6 回/s、100 Hz に対し 1.3 ステップに 1 回
モータ電圧の符号が反転する。実機に持っていけない）。

`−k‖Δa‖²` の罰（exp_006）は k = 1e-4 / 1e-3 / 1e-2 の 3 本ともゼロからの学習で完走率
0.05〜0.10、**すべて衝突**で失敗した。案 1（exp_005 から微調整）は走行能力は保ったが
反転が 75.6 → 65.9 とほとんど下がらず不十分。案 3（高周波成分だけを罰する）が本命。

## 2. 教授の判断: 案 3 の実装より先に、**exp_006 の結論を検証する**

前任者は exp_006 の結果から「**滑らかさと曲がる能力は根本的にトレードオフ**」と結論した。
しかしこの結論には**説明できていない事実**が 1 つ残っている（前任者自身が「未解明」と
記録している）:

> k = 1e-4 の罰は時間罰 0.001 に対して**小さい**にもかかわらず、完走率だけが 0.93 → 0.05 に
> 崩れた。方策の標準偏差（探索の広さ）も対照とほぼ同じだった。「探索が止まったから」では
> 説明がつかない。

**この崖が説明できないまま案 3 に進むのは危険である。**理由は 2 つ:

1. もし失敗の原因が「罰の形（‖Δa‖² が舵まで罰する）」ではなく**別の機構**なら、罰の形を
   変える案 3 は的を外している
2. もし原因が**学習そのものの脆さ**（seed を変える／報酬をわずかに変えるだけで別の悪い解に
   落ちる）なら、案 3 を 1 本回して得られる結果も**単独では解釈できない**

そこで、**案 3 の学習を回す前に（または並行して）、次の 3 つを実施する**。
いずれも計算量は小さい。

### タスク A: 既存ログの再分析（学習不要・最優先）

exp_006 の 4 本（k = 0 / 1e-4 / 1e-3 / 1e-2）は、5 万ステップごとに検証帯の完走率を
記録している。**この学習曲線を 4 本重ね描きし、崩れ方の形を見る。**

**予測を先に登録すること**（`docs/RESEARCH_PLAN.md` §9 の実験規律）。対立する 2 仮説:

- **H-A「初期に潰される」**: 罰は小さいが**符号が一貫している**ため、壁回避を学ぶ前に
  舵の自由度が奪われる。→ 予測: k>0 の 3 本は**最初から完走率が立ち上がらない**
- **H-B「立ち上がってから崩れる」**: いったん走れるようになった後に罰が効いて崩壊する。
  → 予測: 一度 0.5 前後まで上がってから落ちる

**どちらの観測になるかを見てから解釈すること。**H-A なら「トレードオフ」ではなく
「**学習の初期条件の問題**」であり、案 3 でも同じことが起きうる（対策: 罰を学習の途中から
入れる ＝ カリキュラム）。H-B なら罰の形の問題である公算が高く、案 3 が効く。

### タスク B: 割引後の総収益の再計算（机上・学習不要）

`handover/student_b.md` に明記されている手順:

> **新しい報酬項を入れる前に、必ず割引後の総収益を代表条件で計算し、
> ゴール > 探索 > 滞留 > 衝突 の順序を確かめる**（exp_004/005 で確立した手順）

**exp_006 ではこの手順が実施された形跡がない**（`design_highpass.md` §4 は 1 ステップあたりの
罰の大きさを時間罰と比べているだけで、総収益の順序を確認していない）。

`γ = 0.995`・`Δt = 0.01 s`・時間罰 0.001・衝突罰 −1.0 のもとで、次を計算して表にすること:

- exp_006 の 3 条件（k = 1e-4 / 1e-3 / 1e-2、罰の平均は実測 ‖Δa‖² = 3.873 を使う）
- 案 3 の候補（α = 0.5、罰の平均は実測 ‖a−ā‖² = 0.483。k は複数点）
- 各条件について **ゴール到達 / 途中で衝突 / 滞留** の割引後総収益

**着眼点**: 毎ステップほぼ一定量の罰が入るということは、**実効的に時間罰を増やしている**のと
同じである。前任者が踏んだ地雷 3（「時間罰を上げる案は Φ オフセットと数学的に等価で、
破綻の仕方まで同じ」）と同じ構造で、**早く終わること＝衝突に価値を与える**可能性がある。
ゴール到達エピソードの方が長いぶん罰を多く受けるので、**k が大きいほど ゴール と 衝突 の
差が縮む**はずである。どの k で順序が崩れるか、その閾値を求めること。

**教授も独立に概算を持っている。数値は渡さないので、まず自分で計算して報告すること**
（結論を先に渡すと検算にならないため）。食い違えばそこを詰める。

**この計算の結果は案 3 の k の選定に直接使う。**案 3 の k は「順序が余裕をもって保たれる
範囲」から選ぶこと。`design_highpass.md` の第一候補 k = 2.0e-3 が範囲内かを確認し、
範囲外なら k を取り直すか、**衝突罰を深くして順序を回復させる**（exp_005 で Φ オフセットの
破綻を衝突罰で相殺した前例と同じ手法）。

### タスク C: 対照 k=0 の学習 seed 違い 2 本（反証実験）

**目的**: 「完走率 0.93 という結果が、学習 seed に対して頑健か」を確かめる。

前任者は「対照 k=0 が exp_005 を**全指標で完全再現**した」ことをもって、
学習の再現性が裏づけられたと結論した。しかし**同じ seed で同じ結果が出るのは決定性の確認**
であって、**seed をまたいだ頑健性の確認ではない**。exp_006 の各条件は 1 seed しか回して
いないので、「k のせいで壊れた」と「たまたま良い解に当たったのが k=0 の 1 本だけだった」を
現状のデータでは判別できない。

```bash
# 2 本を並行実行（OMP_NUM_THREADS=2 を付ければ 8 コアで同時に回る）
.venv/bin/python experiments/exp_003_sensor_history/train.py --n-envs 1 \
    --potential-offset --collision-penalty -1.0 --seed 1 \
    --log-dir logs/exp_006c_seed1 --model-out models/exp_006c_seed1.zip
# --seed 2 で同様
```

**判定**: 3 本（seed 0 / 1 / 2）とも gate 完走率 0.9 台なら、学習は seed に頑健であり、
exp_006 の「k の効果」は本物と確定する。**1 本でも 0.1 未満に落ちれば、exp_006 の結論
（k のせいで失敗）は成立せず、以後の判定はすべて複数 seed でしか下せない**ことになる。

この結果は M2 以降の実験設計すべてに影響する。**最優先で走らせて、待っている間に
タスク A・B を進めること。**

## 3. 案 3 の実装（タスク A〜C と並行して着手してよい）

`experiments/exp_006_action_smoothness/design_highpass.md` のとおり。

```
ā_t = α·ā_(t−1) + (1 − α)·a_t          （ā_(−1) = 0）
r ← r − k·‖a_t − ā_t‖²
```

- `mouse/corridor_env.py` に低域通過成分 ā を持たせる。**既存の
  `action_smooth_penalty`（‖Δa‖² 版）は消さず、別の引数として追加**すること
  （exp_006 の再現性を壊さない）
- **α = 0.5 固定で k のみ探索**（1 実験 1 変更）。k はタスク B の結果を見て決める
- **ゼロからの学習で試す**（案 3 の狙いは「ゼロから学習しても舵を潰さない」ことなので、
  微調整で確認しても設計の検証にならない）。余力があれば微調整版も
- ā は**報酬計算にのみ使う環境側の内部量**であり、方策の出力をフィルタするものではない。
  入出力契約に触れないという裁定は有効

**判定基準（3 つ同時。exp_006 と同じ）**: 符号反転 10 回/s 未満・完走率 90% 以上・
速度低下 20% 以内（1 区画 0.171 → 0.205 s 以内）。**横偏差（最大・RMS）も併記**すること
（exp_005 の基準値は 最大 52.0 mm・RMS 14.5 mm で、接触水準 54 mm にほぼ達している）。
