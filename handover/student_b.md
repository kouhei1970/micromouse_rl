## 🔴 いまの詰まり: 条件 C の (L) が落ちる（`2b405ec`）

裁定 R32 で**条件 C の場を「点の測地」から「配置空間の測地」へ変更**した
（点の測地は実機中心が辿れない経路の距離を返すので用途に合わない代理量、という理由）。
実装は `_geo_allowed_mask()` ＋ 2 段 Dijkstra。**その結果 (L) が落ちた。**

```
到達可能域に限定した (L)   刻み 6.0 / 1.5 / 0.375 mm
  点の測地＋双線形（旧）    最大比 1.0000 / 1.3107 / 1.3883   ← 収束していた
  配置空間＋双線形（現）    最大比 1.0000 / 5.3848 / 6.0061   ← **収束しない**
```

**2 つの可能性を区別できていない**（ここから始めること）:

1. **実装の欠陥**: 距離場を到達可能な格子点だけで解いた後、双線形が inf を掴まないよう
   帯へ値を延長している。**その延長値がマスク境界付近で双線形に混ざる**。

### 欠陥 D1（区画内 18 件）: **折れ区画の内側・角の二等分線上に真の不連続がある**

`corridor_gen.remaining_path_length()` は**垂線距離が最小の線分**を選ぶ。折れ線
[w_in, center, w_out] が曲がる区画で、機体が**内側を斜めに横切る**と、角の二等分線を
またいだ瞬間に選ばれる線分が 0 → 1 へ切り替わり、弧長 ℓ が飛ぶ。

**対立仮説で判別済み**（「勾配が急なだけ」なら刻みを細かくすると \|ΔΦ\| は比例して減る）:

```
面7004 直進 step55、区画 (5,5)、変位 22.2 mm
  刻み     1 分割 (22.2334 mm/刻み) → 最大 1 刻み |ΔΦ| = 0.068195 m
  刻み    10 分割 ( 2.2233 mm/刻み) → 0.060942
  刻み   100 分割 ( 0.2223 mm/刻み) → 0.059368
  刻み  1000 分割 ( 0.0222 mm/刻み) → 0.059168
  刻み 10000 分割 ( 0.0022 mm/刻み) → 0.059150   ← 減らない ＝ **真の不連続**
```

跳びの大きさは **√2·ρ**（ρ = 区画中心から内側二等分線に沿った距離）で、実測と
**1.4e-9 の精度で一致**（ρ = 0.01〜0.08 m の 7 点で検証）。機体中心が壁から 0.0395 m
以上離れる範囲（＝実際に通れる位置）での**最大跳びは 0.12414 m ＝ 区画寸法の 0.69 倍**。

**速度には依存しない**（刻み 0.0022 mm でも残るので、遅く走っても同じ大きさで起きる）。
検証帯 20 面で**曲がる構成は 1379 通り／曲がる区画 450 個**なので、稀な事象ではない。

### 欠陥 D2（前進 8 件）: **tie-break が選ばなかった降下開口部を通ると跳ぶ**

`_descending_neighbor()` は同点の降下隣接を `min(cands)` ＝座標の辞書順で選ぶ。
**機体がその選ばれなかった方の開口部から出て前進すると**、Φ が別の経路の残り距離へ


## 報酬設計の到達点（このプロジェクトで最も苦労した箇所・必読）

現行の報酬（exp_005 で確定、`mouse/corridor_env.py`）:

```
r = γ·Φ(s') − Φ(s) − 0.001              Φ = D₀ − (残り経路長)   ← potential_offset=True
  + 1.0   （ゴール到達）
  − 1.0   （衝突・転倒）                                        ← collision_penalty=-1.0
  − k‖a_t − a_(t−1)‖²                                          ← exp_006。**現状は k=0 が最良**
```

D₀ = 2.52 m での割引後の総収益: **ゴール 0.627 > 衝突 0.285 > 滞留 −0.200**。

**踏んではいけない地雷（実際に踏んだ 5 件）**:

1. Φ = −D（オフセットなし）だと**滞留が 2 位**（2.320）でゴールとの差が 0.267 しかなく、
   学習が滞留解に落ちる（exp_003 で実際に落ち、exp_003b でも 20〜25 万で一時的に落ちた）
2. Φ にオフセットを足すだけだと**衝突がゴールより得**になる（0.890 > 0.627）。終端で Φ ≠ 0
   になるため γ^T·Φ(s_T) が「早く終わること」にボーナスを与えるのが原因。exp_004 で実証
3. 「時間罰を上げる」案は Φ オフセットと**数学的に等価**で、破綻の仕方まで同じ
   （F' = F + (γ−1)c。時間罰を上げること自体が「早く終わること」に価値を与える）
4. 「終端で Φ=0 と強制する」実装は**してはいけない**（最後の遷移で
   F = γ·0 − Φ(s_{T−1}) = D_{T−1} > 0 となり、衝突した瞬間に正の報酬が入る）
5. 本設計は**理論的にクリーンではない**（終端 Φ≠0 が生む早期終了ボーナスを衝突罰で
   相殺している）。動いているが、別のタスクへ流用するときは再検算すること

**新しい報酬項を入れる前に、必ず割引後の総収益を代表条件で計算し、
ゴール > 探索 > 滞留 > 衝突 の順序を確かめる**（exp_004/005 で確立した手順）。
